# Рецензия: спецификации, тесты, код

Дата: 2026-09-08. Проверено: 95 тестов проходят (актуализировано 2026-09-10, changes `fix-diff-colors-and-table-fallback`, `harden-tests`, `spec-alignment`).

Актуализировано 2026-09-15 (change `formatted-document-view`): 109 тестов
проходят. Контракт конвертера — блоки `{text, html, images}` вместо
Markdown-строки (спека markdown-conversion обновлена, разбиение на блоки
перенесено в конвертер; в document-diff осталась «Нормализация блоков
документа»). Служебная строка-разделитель таблиц более не эмитится.
Новое покрытие: HTML-представление блоков (экранирование, форматирование,
инвариант textContent == text), извлечение изображений (лимит, пропуск
битых), `normalize_blocks`, `images_changed` (замена картинки при том же
тексте). Клиентская логика рендера (вплетение пословного diff в HTML,
таблицы из `<td>`-фрагментов, fallback при расхождении html и текста,
рамки изображений) проверена одноразовым jsdom-сценарием (в репозитории
не оставлен — клиент по-прежнему без постоянных тестов, см. раздел 1).
Осознанные ограничения (design Non-Goals): форматирование, наследуемое из
стилей docx, не отображается (только прямые атрибуты runs); изменение
только форматирования без изменения текста не детектируется; постраничный
вид «как на печать» не реализован.

Актуализировано 2026-09-15 (change `fix-one-sided-row-classification`):
113 тестов проходят. Исправлен дефект: односторонняя строка результата
(чистый insert/delete или хвост replace-фрагмента), классифицированная
LLM как `changed` (например, абзац только с картинкой — LLM видит
«(пусто)» с обеих сторон), оставляла заглушку без подсветки. Теперь
класс односторонней строки структурный (`removed`/`added`), метка
классификации действует только на парные строки; поведение semantic и
degraded режимов уравнено. Покрыто тестами `TestOneSidedRowClassification`.

Актуализировано 2026-09-17 (change `image-subrow-alignment`): 118 тестов
проходят. Исправлен дефект: картинка, добавленная/удалённая/заменённая
внутри абзаца с неизменным текстом, была невидима для текстового diff —
строка оставалась парной, место вставки/удаления в противоположной панели
не подсвечивалось. Теперь у парных блоков с различающимся набором
изображений изображения выносятся из текстовой строки в под-строки,
выровненные по подписям sha1: совпавшие — парные без подсветки,
односторонние — структурные `removed`/`added` с цветной заглушкой
напротив, пара разных на парной позиции — под-строка замены с
`images_changed` у обеих сторон (красная/зелёная рамки, высоты
выровнены). Применяется единообразно к equal-строкам и changed-парам;
таблицы и лимит `MAX_IMAGES_BYTES` — вне области (прежнее поведение).
Клиент без изменений. Покрыто тестами `TestImageSubrows` (5 шт.);
ожидание `test_same_text_different_images_marked` обновлено под новую
структуру `rows[]`.

## 1. Требования, для которых нет проверок

**Вся клиентская часть (app.js / index.html / style.css) не покрыта тестами вообще**, поэтому без проверок остаются:

- **comparison-jobs / «Визуализация процесса обработки»**: степпер виден всегда и неподсвечен до запуска; активный/завершённый/ошибочный этапы; первый опрос немедленно, далее — каждую 1 секунду; поведение степпера при успехе и ошибке.
- **file-upload / «Выбор файлов на веб-странице» и «Активация кнопки»**: drag-and-drop, отображение имени файла, сообщение об ошибке валидации в UI, disabled-логика кнопки «Начать сравнение».
- **diff-viewer / «Синхронная прокрутка»**.
- **diff-viewer / «Отображение side-by-side»**: требования к высотам (парные блоки — высота большей стороны; пустое место — высота удалённого/добавленного блока; таблицы обеих панелей — одинаковая высота; `equalizeHeights`).
- **diff-viewer / «Цветовая подсветка»**: цвета фонов, метки-полосы в UI, запрет жёлтого в подсветке различий, «подкладка короткой стороны без цветного фона», желто-зелено-серая палитра — ничем не проверяются (даже косвенно).
- **diff-viewer / «Индикация деградированного режима»**: серверный флаг `semantic` проверен, само отображение уведомления — нет.
- ~~**diff-viewer / fallback пословного diff**~~ — **исправлено** (changes `fix-diff-colors-and-table-fallback`, `harden-tests`): путь `inline_diff → None` покрыт для табличных ячеек (`test_table_cell_fallback_highlights_whole_cell`) и для обычных блоков (`test_changed_block_without_inline_diff_has_no_segments`).
- ~~**comparison-jobs / асинхронность**~~ — **исправлено** (change `harden-tests`): потоковый путь `start_job` покрыт тестом `test_threaded_job_pipeline_sets_stages_and_completes` (processing → done, этапы от пайплайна, результат через API).
- ~~**comparison-jobs / порядок этапов**~~ — **исправлено** (change `harden-tests`): последовательность converting → diffing → llm проверена целиком в `test_llm_stage_during_classification`.
- ~~**llm-classification**: системный промпт и `base_url`~~ — **исправлено** (change `harden-tests`): `test_system_prompt_is_russian` (промпт на русском, мок инспектирует сообщения), `test_base_url_from_config` (`base_url` из `LLM_BASE_URL`).
- ~~**markdown-conversion**: заголовки уровней 3–6 и клампинг~~ — **исправлено** (change `harden-tests`): `test_heading_levels_3_to_6`, `test_heading_level_clamped_to_6`.
- ~~**file-upload**: уникальность имени сохраняемого файла~~ — **исправлено** (change `harden-tests`): `test_upload_same_name_twice_saves_both`.
