Актуализировано 2026-10-07 (change `add-pdf-comparison`): 229 тестов
проходят, плюс два сквозных сценария. Добавлена поддержка `.pdf` двумя
ветками: текстовый слой через `pdfplumber` (детерминированно, без модели) и
скан через vision-модель (постранично, по одному запросу на страницу).
Контракт блока расширен необязательными полями `page` и `crops`; для `.docx`
они не эмится. Введён `convert_pdf_pair(path1, path2)` — парная точка входа,
потому что решение «какую страницу не читать» невозможно без второго
документа: страницы сопоставляются по маске разности **до** первого
обращения к модели, совпавшие не читаются и не дают блоков, а показываются
свёрнутыми диапазонами; изменённые страницы показываются целиком. Номера
страниц — только метаданные подписи, в вычислении различий не участвуют.
Страницы, которые не удалось прочитать, не сворачиваются «как неизменённые»:
они показываются отдельной строкой с признаком деградации. В пайплайн
добавлено необязательное поле `stage_progress`, ключи этапов не изменились.
Клиент научился бейджу страницы, кропам и раскрытию диапазона через новый
`POST /api/jobs/<id>/pages` (добывает текст страниц по запросу).

Проверено сквозными сценариями (в репозитории оставлены, требуют только
`PYTHONPATH=.`): `tests/manual_scan_check.py` — 30 проверок полного пути на
сканах через HTTP, включая деградацию при недоступной модели и совместимость
`.docx`; `tests/real_model_check.py` — чтение страниц настоящей
`qwen3-vl-8b`.

Измеренные пороги (раньше стояли «на глаз» и ломали результат молча):

- `MATCH_IOU_THRESHOLD = 0.35` по доле пересечения масок чернил. Правка
  символа даёт 0.91, правка в конце строки 0.47, переписанный абзац 0.32,
  разные страницы одного документа 0.20–0.26. Прежний порог 0.6 терял
  сопоставление при сильной правке: страница уходила в «только в одном
  файле» и **кроп визуально правки не строился вовсе** — найдено только
  сквозным сценарием.
- `IDENTITY_IOU_THRESHOLD = 0.999` — страница считается совпавшей и не
  читается только при почти полном совпадении.
- `CHANGE_RATIO_THRESHOLD = 0.00005`: правка цифры даёт 0.0005 площади
  страницы, шум подложки после бинаризации — ровно ноль пикселей. Порог
  выбран между ними; ошибка допустима только в сторону «зря позвали модель».
- `MIN_REGION_RATIO = 0.00005` — мелкие связные компоненты отбрасываются как
  шум сканирования.

Дефекты, найденные при реализации и исправленные:

- **`skimage.transform.rotate` обнулял бинарную маску.** Для целочисленных
  массивов библиотека переносит диапазон в `[0,1]`, и значения `0/1`
  превращались в нули: оценка наклона молча возвращала 0 для любой страницы.
  Нужен `preserve_range=True`. Найдено потому, что тест проверял конкретное
  значение, а не «вызвалось без ошибки».
- **Подобие страниц по доле пикселей было фиктивным**: страница на 99.9%
  белая, поэтому любые две страницы давали ~0.998. Заменено на IoU по маске
  чернил.
- **Пустые свёрнутые диапазоны**: при совпадении первой страницы вставлялась
  строка `[1, 0]`, и раскрытие такого диапазона падало. Диапазон вставляется
  только если непуст.
- **`_group_by_page` падал с `KeyError: 0` при полном совпадении документов** —
  ровно в самом частом случае: строк нет, границ нет.
- **`PDF_RENDER_DPI` приходил строкой** из конфигурации, `dpi / 72` давал
  `TypeError`. Приводится к `int` в рендере.
- **Деградация не поднималась** на страницах, которые модель не должна была
  читать и не прочитала. Теперь `unreadable` считается как разность
  «подлежало чтению» минус «получили блоки».

Дефект, найденный при ручной проверке в браузере и исправленный
(change `fix-pdf-identical-notice`):

- **Сравнение различающихся PDF сообщало о полном совпадении.** Клиент
  показывал сообщение, когда список неизменённых страниц пуст, то есть ровно
  когда документы различаются, и выбрасывал при этом посчитанные строки
  результата (проверено: 6 фрагментов, 15 строк потеряно). Для действительно
  одинаковых PDF сообщения, наоборот, не было — вместо него рисовался
  свёрнутый диапазон. Решение перенесено на сервер: в результате задачи
  появился признак `identical`, считаемый по фрагментам, разнице изображений
  в строках, выравниванию страниц и состоянию чтения.
- **Неизменённая страница показывалась дважды.** В ветке текстового слоя
  страница давала и своё содержимое, и свёрнутую строку диапазона: текст
  доступен бесплатно, поэтому она конвертировалась целиком. Блоки совпавших
  страниц теперь исключаются до сравнения — так же, как ветка чтения моделью
  их не читает.

## 1. Требования, для которых нет проверок

**Вся клиентская часть (app.js / index.html / style.css) не покрыта тестами вообще**, поэтому без проверок остаются:

Новые требования change `add-pdf-comparison` без автоматических проверок:

- **diff-viewer / «Отображение номера страницы»**: бейдж страницы в строке;
  для совпадающих блоков — номера обеих сторон; пустое место номер не
  показывает. Серверная часть (`page` в сторонах строк) проверена; отрисовка —
  нет.
- **diff-viewer / «Отображение визуально изменённых областей»**: кропы с
  рамкой, привязка к странице, отсутствие кропов у неизменённых страниц,
  поведение при усечении. Данные проверены сквозным сценарием; отрисовка — нет.
- **diff-viewer / «Свёртывание неизменённых страниц»**: свёрнутая строка,
  раскрытие и повторное сворачивание, диапазон из одной страницы. Вставка
  свёрнутых строк в результат проверена (`test_pdf_pipeline.py`), поведение
  клиента — нет. **Сообщение о полном совпадении** вынесено из клиента на
  сервер (change `fix-pdf-identical-notice`): признак `identical` в результате
  задачи покрыт тестами на каждом условии (`TestIdenticalFlag`,
  `TestIdenticalFlagInResult`), отрисовка самого сообщения по-прежнему не
  покрыта.
- **comparison-jobs / «Прогресс конвертации многостраничных документов»**:
  само значение `stage_progress` проверено, отображение «12 из 45 страниц» —
  нет.
- **page-image-diff / «Рендер страниц PDF» и «Консервативный порог…»**:
  покрыты тестами на синтетических сканах, но не на фотографиях реальных
  документов: наклон, неравномерность подложки и артефакты печати в тестах
  не воспроизводятся.
- **Клиентский раскрытие диапазона** (`toggleRange`): состояние
  `expandedRanges`, повторное нажатие, сообщение об ошибке загрузки.

Прежние без проверок:

- **comparison-jobs / «Визуализация процесса обработки»**: степпер виден всегда и неподсвечен до запуска; активный/завершённый/ошибочный этапы; первый опрос немедленно, далее — каждую 1 секунду; поведение степпера при успехе и ошибке.
- **file-upload / «Выбор файлов на веб-странице» и «Активация кнопки»**: drag-and-drop, отображение имени файла, сообщение об ошибке валидации в UI, disabled-логика кнопки «Начать сравнение».
- **diff-viewer / «Синхронная прокрутка»**: вертикальная синхронизация; с 2026-10-05 также горизонтальная (обе оси) и отсутствие отскока панели при разной ширине прокручиваемого содержимого. Автотестов нет; эхо-защита и горизонтальная синхронизация проверены headless-Chrome сценарием с реальными максимумами прокрутки (не в репозитории).
- **diff-viewer / «Ширина колонок широких таблиц» и «Единый источник горизонтальной прокрутки»** (новые требования, 2026-10-05): пол `4em`, потолок содержимого `40em`, отсутствие вложенных горизонтальных полос, прибитый заголовок панели, запрет брать ширины колонок из документа. Автотестов нет (правила CSS); проверено headless-Chrome на реальном `.docx` (таблица 14 колонок: минимальная колонка 64px = 4em, 46px под текст, вложенных полос нет, страница по горизонтали не прокручивается).
- **diff-viewer / «Отображение side-by-side»**: требования к высотам (парные блоки — высота большей стороны; пустое место — высота удалённого/добавленного блока; таблицы обеих панелей — одинаковая высота; `equalizeHeights`).
- **diff-viewer / «Цветовая подсветка»**: цвета фонов, метки-полосы в UI, запрет жёлтого в подсветке различий, «подкладка короткой стороны без цветного фона», желто-зелено-серая палитра — ничем не проверяются (даже косвенно).
- **diff-viewer / «Индикация деградированного режима»**: серверный флаг `semantic` проверен, само отображение уведомления — нет.
- ~~**diff-viewer / fallback пословного diff**~~ — **исправлено** (changes `fix-diff-colors-and-table-fallback`, `harden-tests`): путь `inline_diff → None` покрыт для табличных ячеек (`test_table_cell_fallback_highlights_whole_cell`) и для обычных блоков (`test_changed_block_without_inline_diff_has_no_segments`).

## 4. Решения, принятые без указания

Решения change `add-pdf-comparison`, не закреплённые ни в одном требовании:

- **Подобие страниц по IoU, а не по доле пикселей** — доля пикселей не
  работает (страница на 99.9% белая, любые две дают ~0.998). Пороги
  зафиксированы в `page_image_diff` комментарием с замерами, но в спеку не
  вынесены: числовые пороги традиционно не специфицируются (ср. раздел 4,
  «Числовые пороги»).
- **Оценка наклона дискретным перебором углов** вместо градиентного метода —
  выбрана ради воспроизводимости: результат не зависит от версии библиотеки.
  Дискретность шага 0.25° не специфицирована.
- **`skimage.transform.rotate` требует `preserve_range=True` для целочисленных
  массивов** — задокументировано в коде, в спеку не вынесено как поведение
  системы.
- **Раскрытие свёрнутого диапазона платное и одностороннее**: совпавшая
  страница читается с одной стороны, вторая идентична по построению. В
  спеке записано «с добычей текста страниц» без указания стороны.
- **Фикстуры PDF собираются вручную**, минимальным синтаксисом PDF: это дало
  контроль над отсутствием текстового слоя (различие проверяемых веток), но
  ограничивает алфавит — текстовый слой использует WinAnsiEncoding, поэтому
  кириллица в нём непредставима и фикстуры с текстовым слоем латинские.
  Кириллица покрыта тестами конвертера `.docx`.
- **Ветка текстового слоя вызывает `load_pages` дважды** (для выравнивания и
  для кропов) — цена рендера, не влияющая на результат; осознанно не
  оптимизировано, чтобы не держать в памяти все страницы документа.
- **`.env.example` по-прежнему содержит боевой адрес LLM** — задача 2.3
  отложена; риск раскрытия внутренней топологии при клонировании репозитория
  зафиксирован в design.md (Risks) и в proposal.
