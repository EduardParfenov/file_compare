# file_compare

Веб-приложение для сравнения двух версий документов. Сейчас поддерживается
`.docx` и `.pdf` (включая сканированные), в планах — `.xlsx`.

## Требования

- Python 3.11

## Установка и запуск

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # при необходимости отредактировать
flask run
```

Приложение будет доступно по адресу http://127.0.0.1:5000

- `GET /` — главная страница (загрузка файлов, степпер этапов, diff viewer)
- `GET /health` — проверка состояния (`{"status": "ok"}`)
- `POST /api/upload` — загрузка файла (multipart, поле `file`) → `{"upload_id", "filename"}`
- `POST /api/compare` — запуск сравнения (`{"upload_id_1", "upload_id_2"}`) → `202 {"job_id"}`
- `GET /api/jobs/<job_id>` — статус задачи: `processing` (с ключом этапа
  `stage` и `stage_message`), `done` (с `result`) или `failed` (с `error`).
  Клиент опрашивает каждую 1 секунду (первый запрос — сразу после старта)

## Как это работает

1. Загруженные документы конвертируются в упорядоченные блоки (заголовки,
   абзацы, строки таблиц). Для `.docx` — `python-docx`, для `.pdf` с
   текстовым слоем — `pdfplumber`, для сканов без слоя — страницы читаются
   vision-моделью (см. «Чтение страниц сканов»). Каждый блок содержит текст
   (для сравнения и LLM), форматированный HTML (для отображения) и
   изображения (data-URI, с лимитом суммарного размера).
2. Различия между текстами блоков ищутся алгоритмически (`difflib`).
   Фрагменты `replace` дополнительно уточняются по похожести текстов
   блоков: похожие пары — изменения, непохожие — удаления и добавления
   (так удалённый/добавленный текст не маскируется под изменённый).
   Изображения парных блоков сравниваются по хэшу: замена картинки при
   неизменном тексте помечается `images_changed`.
3. Каждый различающийся фрагмент классифицируется LLM
   (изменено / удалено / добавлено). Если LLM недоступна, классификация
   выполняется по опкодам difflib, а результат помечается
   `semantic: false` (в UI — уведомление о деградации).
4. Результат отображается side-by-side в форматированном виде (заголовки,
   жирный/курсив, списки, таблицы, изображения) с подсветкой и
   синхронным скроллом. Подсветка двухцветная: удалённое — красным,
   добавленное — зелёным. Внутри изменённых блоков — пословная
   подсветка, вплетённая в форматирование документа; удалённые/добавленные
   блоки целиком — красный/зелёный фон. Таблицы отображаются как
   HTML-таблицы (пословная подсветка внутри ячеек, цветные строки для
   добавленных/удалённых), изображения — с цветными рамками при
   добавлении/удалении/замене. Для PDF дополнительно: номер страницы,
   кропы визуально изменённых областей и свёрнутые диапазоны совпавших
   страниц (их текст добывается по запросу).

## Тесты

```bash
pytest
```

Дополнительно, вне `pytest` (нужен только `PYTHONPATH=.`):

```bash
PYTHONPATH=. python tests/manual_scan_check.py   # сквозной путь на сканах
```

`tests/real_model_check.py` требует настоящую модель: `LLM_BASE_URL`,
`LLM_API_KEY` и `LLM_MODEL` передаются окружением, ключ в файлы не пишется.

Вся конфигурация задаётся через переменные окружения (см. `.env.example`):

| Переменная           | Описание                                  |
|----------------------|-------------------------------------------|
| `FLASK_APP`          | Точка входа Flask (`app`)                 |
| `FLASK_DEBUG`        | Режим отладки (0/1)                       |
| `SECRET_KEY`         | Секретный ключ Flask                      |
| `LLM_BASE_URL`       | Базовый URL OpenAI-совместимого LLM API   |
| `LLM_API_KEY`        | API-ключ LLM                              |
| `LLM_MODEL`          | Название модели LLM                       |
| `LLM_EXTRA_BODY`     | Доп. параметры тела запроса к LLM (JSON, опционально) |
| `UPLOAD_DIR`         | Каталог для загружаемых файлов            |
| `MAX_CONTENT_LENGTH` | Максимальный размер загрузки (байты)      |
| `MAX_IMAGES_TOTAL_BYTES` | Лимит суммарного размера изображений, извлекаемых из документа (байты) |
| `ALLOWED_EXTENSIONS` | Разрешённые расширения (через запятую)    |
| `LOG_LEVEL`          | Уровень журнала (`WARNING` по умолчанию)  |

### Чтение страниц сканов

Чтение страниц использует ту же модель, что и классификация фрагментов
(`LLM_MODEL`, `LLM_BASE_URL`, `LLM_API_KEY`). Отдельные настройки модели не
вводятся: различаются только параметры вызова.

| Переменная            | По умолчанию | Описание                              |
|-----------------------|--------------|---------------------------------------|
| `OCR_TIMEOUT`         | `120`        | Таймаут чтения одной страницы, с     |
|                       |              | (страница читается дольше, чем        |
|                       |              | классифицируется фрагмент)            |
| `OCR_CONCURRENCY`     | `4`          | Число одновременных запросов к модели |
| `OCR_PROMPT_VERSION`  | `v1`         | Версия инструкции; входит в ключ      |
|                       |              | кэша, изменение перечитывает страницы |
| `PDF_RENDER_DPI`      | `200`        | Разрешение рендера страниц PDF        |
| `PDF_CROPS_MAX_BYTES` | `4194304`    | Лимит суммарного объёма кропов на     |
|                       |              | документ (4 МБ)                       |

### Журнал

Журнал пишется в стандартный поток вывода (stderr) и содержит причины тех
сбоев, которые приложение проглатывает и продолжает работу: недоступность
модели при чтении страниц, сбой классификатора, пропущенные при разборе
страницы и изображения, ошибка задачи сравнения.

| Переменная  | По умолчанию | Описание                                  |
|-------------|--------------|-------------------------------------------|
| `LOG_LEVEL` | `WARNING`    | `CRITICAL`, `ERROR`, `WARNING`, `INFO`, `DEBUG` |

Неизвестное значение не мешает запуску: применяется уровень по умолчанию, а в
журнал попадает запись о неверном значении. Для разбора деградации удобно
`LOG_LEVEL=DEBUG`.

Чего в журнале нет и почему:

- текст блоков документов, содержимое изображений и кропов — журнал попадает
  в вывод процесса и в журналы CI, документ там быть не должен;
- адрес и ключ внешнего сервиса — в текстах ошибок сторонних клиентов они
  встречаются, поэтому в запись попадает только **тип** исключения
  (`ConnectionError`, `TimeoutError` и т. п.), а не его текст;
- тела запросов и ответов модели.

Журналирование не меняет формат ответов API и результат сравнения: сбой записи
в журнал не прерывает задачу.

### Ограничение: чтение страниц моделью не авторизовано по умолчанию

Если `LLM_API_KEY` пуст, эндпоинт модели принимает запросы без аутентификации —
при условии, что сетевой доступ к нему кто-либо имеет. Для внутреннего
контура за файрволлом это обычная практика, но решение стоит принять осознанно:

- скан документа уходит на эндпоинт, доступный любому, кто дотянется до сети;
- незаданный адрес при развёртывании даст ошибку соединения вместо тихой
  неработоспособности;
- адрес модели не должен попадать в репозиторий: `.env.example` содержит
  пустые значения намеренно, реальные — только в `.env` (в `.gitignore`).

### Как устроено сравнение PDF

```
PDF с текстовым слоем            скан без текстового слоя
────────────────────────         ────────────────────────────
pdfplumber: абзацы, таблицы,      рендер страниц (pypdfium2)
картинки, координаты слов        ↓
детерминированно, БЕЗ модели     маска разности страниц (page_image_diff)
                                  ↓
                                  выравнивание страниц
                                  ↓
                                  qwen3-vl читает ТОЛЬКО изменённые
                                  страницы, по одной на запрос
                                  ↓
                                  markdown -> блоки -> прежний diff
```

Страницы, совпавшие визуально, не читаются и не дают блоков — они показаны
свёрнутым диапазоном. Изменённые страницы показаны целиком, с пословной
подсветкой и кропами визуально изменённых областей. Страница, которую не
удалось прочитать, **не** сворачивается как неизменённая: она отображается
отдельной строкой, а результат помечается деградированным.

Раскрытие свёрнутого диапазона добывает текст страниц по запросу
(`POST /api/jobs/<job_id>/pages`) — это оплачивается вызовами модели, поэтому
развёрнутые страницы читаются с одной стороны: совпадение уже доказано
попиксельно.

Определённость конвертации PDF: ветка текстового слоя детерминирована, ветка
чтения моделью воспроизводима в пределах кэша (ключ — содержимое страницы,
имя модели, версия инструкции).

Ограничения, о которых стоит знать заранее:

- чтение страниц детерминировано моделью, а не кодом: одинаковый вход может
  дать разный текст между перезапусками процесса;
- настоящая vision-модель может пересказывать текст вместо дословного
  переноса — на части страниц это снижает точность текстового diff (визуальный
  кроп при этом остаётся верным);
- для сканов не реализована точная привязка кропа к конкретной строке: кроп
  привязан к странице.
