# document-diff Specification

## Purpose

Алгоритмическое сравнение двух документов на уровне смысловых
блоков (абзацы, заголовки, строки таблиц), чтобы найти различающиеся
фрагменты до семантической классификации.

## Requirements

### Requirement: Нормализация блоков документа
Система SHALL принимать от конвертера упорядоченную последовательность
текстовых блоков и нормализовать их перед сравнением: пробельные
символы (включая неразрывные пробелы) MUST сворачиваться в один обычный
пробел, блоки без содержимого после нормализации (ни текста, ни
изображений) MUST игнорироваться.
Порядок блоков MUST сохраняться. Гранулярность блоков (заголовок,
абзац, строка таблицы) определяется конвертером и MUST NOT
пересматриваться движком сравнения.

#### Scenario: Нормализация пробелов
- **Дано** блоки с неразрывными и повторными пробелами
- **Когда** выполняется нормализация перед сравнением
- **То** последовательности пробельных символов сворачиваются в один обычный пробел

#### Scenario: Пустые после нормализации блоки
- **Дано** блок, состоящий только из пробельных символов, без изображений
- **Когда** выполняется нормализация перед сравнением
- **То** этот блок исключён из сравнения

#### Scenario: Блок только с изображением
- **Дано** блок без текста, но с изображением
- **Когда** выполняется нормализация перед сравнением
- **То** этот блок сохраняется в сравнении

#### Scenario: Порядок блоков сохраняется
- **Дано** последовательность блоков от конвертера
- **Когда** выполняется нормализация перед сравнением
- **То** порядок непустых блоков соответствует порядку следования в документе

### Requirement: Алгоритмический поиск различающихся блоков
Система SHALL сравнивать последовательности блоков двух документов
алгоритмом на основе `difflib` и возвращать список различающихся фрагментов.
Каждый фрагмент MUST содержать тип операции (`replace`, `delete`, `insert`),
старые блоки (из файла 1), новые блоки (из файла 2) и позиции блоков в
обоих документах для последующей подсветки. Идентичные документы MUST
давать пустой список различий.

#### Scenario: Идентичные документы
- **Дано** два одинаковых Markdown-документа
- **Когда** выполняется поиск различий
- **То** список различающихся фрагментов пуст

#### Scenario: Изменённый абзац
- **Дано** в файле 2 изменён текст второго абзаца относительно файла 1
- **Когда** выполняется поиск различий
- **То** возвращается фрагмент с операцией `replace`, содержащий старый и новый текст абзаца

#### Scenario: Удалённый абзац
- **Дано** в файле 2 отсутствует абзац, присутствующий в файле 1
- **Когда** выполняется поиск различий
- **То** возвращается фрагмент с операцией `delete` и старым текстом абзаца

#### Scenario: Добавленный абзац
- **Дано** в файле 2 появился новый абзац, отсутствующий в файле 1
- **Когда** выполняется поиск различий
- **То** возвращается фрагмент с операцией `insert` и новым текстом абзаца

### Requirement: Уточнение replace-фрагментов по похожести
Система SHALL дополнительно разбивать каждый replace-фрагмент,
сопоставляя старые и новые блоки по похожести текстов
(`difflib.SequenceMatcher.ratio`): похожие пары (ratio не ниже порога
`0.6`) остаются `replace`, непарные старые блоки становятся `delete`,
непарные новые — `insert`. Порядок блоков MUST сохраняться, а
подфрагменты MUST без пропусков покрывать область исходного фрагмента.
Это отличает изменённые блоки от удалённых и добавленных, которые
difflib сливает в один replace-фрагмент. Уточнение MUST быть ограничено
по трудоёмкости: если произведение числа старых и новых блоков фрагмента
превышает `2500` пар, фрагмент MUST остаться неуточнённым (остаётся
`replace` целиком).

#### Scenario: Изменённый, удалённый и добавленный абзацы подряд
- **Дано** в файле 2 подряд идут: изменённый абзац, отсутствует абзац из файла 1, добавлен новый абзац
- **Когда** выполняется поиск и уточнение различий
- **То** возвращаются три фрагмента: `replace` для похожей пары, `delete` для удалённого абзаца, `insert` для добавленного

#### Scenario: Полностью непохожие блоки
- **Дано** replace-фрагмент, в котором старый и новый блоки не имеют сходства
- **Когда** выполняется уточнение
- **То** возвращаются фрагменты `delete` (старый блок) и `insert` (новый блок)

#### Scenario: Превышение лимита пар уточнения
- **Дано** replace-фрагмент, в котором произведение числа старых и новых блоков превышает 2500
- **Когда** выполняется уточнение
- **То** фрагмент остаётся неуточнённым и возвращается как единый `replace`
