# comparison-jobs Specification

## Purpose

Асинхронное выполнение сравнения документов с этапными статусами и опросом
состояния, чтобы пользователь видел ход обработки, а не «зависшую»
страницу.

## Requirements

### Requirement: Запуск задачи сравнения
Система SHALL предоставлять эндпоинт `POST /api/compare`, принимающий JSON
с идентификаторами двух загруженных файлов, создающий задачу сравнения и
возвращающий её идентификатор `job_id`. Обработка MUST выполняться
асинхронно: ответ на запрос не дожидается завершения сравнения. Запрос с
неизвестным идентификатором файла MUST отклоняться с кодом 404, запрос
без идентификаторов — с кодом 400.

#### Scenario: Успешный запуск сравнения
- **Дано** загружены два файла с идентификаторами `id1` и `id2`
- **Когда** клиент отправляет `POST /api/compare` с `{"upload_id_1": "id1", "upload_id_2": "id2"}`
- **То** ответ имеет код 202 и содержит `job_id`
- **И** задача сравнения создана и выполняется асинхронно

#### Scenario: Запуск с неизвестным файлом
- **Когда** клиент отправляет `POST /api/compare` с несуществующим `upload_id`
- **То** ответ имеет код 404 и JSON с полем `error`

#### Scenario: Запуск без идентификаторов файлов
- **Когда** клиент отправляет `POST /api/compare` без `upload_id_1` или `upload_id_2`
- **То** ответ имеет код 400 и JSON с полем `error`

### Requirement: Этапные статусы задачи
Задача сравнения SHALL проходить этапы «Конвертация файлов...» → «Поиск
различий...» → «Анализ через LLM...» и завершаться статусом «готово» либо
«ошибка». Система SHALL предоставлять эндпоинт `GET /api/jobs/<job_id>`,
возвращающий текущий статус задачи, сообщение текущего этапа, а при
завершении — результат сравнения (блоки обоих документов и классифицированные
различия) либо сообщение об ошибке. Запрос несуществующей задачи MUST
возвращать код 404.

#### Scenario: Опрос задачи в процессе обработки
- **Дано** задача сравнения запущена и находится на этапе поиска различий
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит статус «в обработке» и сообщение «Поиск различий...»

#### Scenario: Получение завершённой задачи
- **Дано** задача сравнения успешно завершена
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит статус «готово»
- **И** результат со структурой обоих документов и классами различий для каждого фрагмента

#### Scenario: Задача завершилась ошибкой
- **Дано** задача сравнения завершилась ошибкой конвертации
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит статус «ошибка» и сообщение об ошибке

#### Scenario: Запрос несуществующей задачи
- **Когда** клиент запрашивает `GET /api/jobs/<несуществующий_id>`
- **То** ответ имеет код 404 и JSON с полем `error`

### Requirement: Визуализация процесса обработки на клиенте
Во время обработки веб-страница SHALL показывать индикатор загрузки
(спиннер) и статусное сообщение текущего этапа, опрашивая
`GET /api/jobs/<job_id>` с интервалом 3 секунды до получения финального
статуса. После завершения задачи спиннер MUST скрываться: при успехе
отображается результат, при ошибке — сообщение об ошибке.

#### Scenario: Отображение этапов во время обработки
- **Дано** пользователь нажал «Начать сравнение» и задача запущена
- **Когда** задача находится в обработке
- **То** на странице виден спиннер и сообщение текущего этапа
- **И** опрос статуса выполняется каждые 3 секунды

#### Scenario: Завершение обработки с ошибкой
- **Дано** задача сравнения завершилась ошибкой
- **Когда** клиент получает финальный статус
- **То** спиннер скрывается и отображается сообщение об ошибке
