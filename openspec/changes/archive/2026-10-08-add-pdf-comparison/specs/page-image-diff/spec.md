## Purpose

Попиксельное сравнение отрендеренных страниц двух документов: выравнивание
страниц, консервативный порог признания страницы неизменной и извлечение
изображений визуально изменённых областей.

## ADDED Requirements

### Requirement: Рендер страниц PDF
Система SHALL отображать страницы PDF в изображения с разрешением,
настраиваемым через переменную окружения. Рендер MUST выполняться постранично, без одновременного построения изображений
всех страниц документа в памяти, и MUST NOT записывать промежуточные изображения
на диск. Рендер MUST быть детерминированным:
один и тот же файл при одном и том же разрешении даёт одинаковые изображения
страниц. Повреждённая страница MUST приводить к ошибке конвертации с понятным
сообщением, а не к пустому изображению.

#### Scenario: Рендер страницы
- **Дано** загружен PDF на несколько страниц
- **Когда** выполняется рендер страниц
- **То** получено изображение каждой страницы с заданным разрешением
- **И** промежуточные файлы на диске не создаются

#### Scenario: Повторяемость рендера
- **Дано** один и тот же PDF отрендерен дважды при одном разрешении
- **Когда** сравниваются изображения страниц
- **То** изображения совпадают

#### Scenario: Повреждённая страница
- **Дано** файл с расширением `.pdf`, содержащий повреждённую страницу
- **Когда** выполняется рендер этой страницы
- **То** возвращается ошибка с понятным сообщением

### Requirement: Консервативный порог признания страницы неизменной
Система SHALL сравнивать страницы попиксельно после приведения к общему виду
и определять, совпадают ли они визуально. Порог признания страницы неизменной
MUST быть выбран так, чтобы характерный шум сканирования (неравномерность
подложки, артефакты сжатия, пыль, смещение растра) никогда не приводил к
признанию страницы неизменной. Ложное признание изменённой страницы
неизменной, способное скрыть правку, MUST NOT возникать. Ложное признание
неизменной страницы изменённой допустимо: оно приводит лишь к лишней работе.
Для сканированных страниц сравнение MUST выполняться после устранения наклона
и перевода в чёрно-белое представление, чтобы шум подложки не маскировал и не
создавал различий.

#### Scenario: Шум сканирования без правок
- **Дано** две версии страницы, отличающиеся только шумом сканирования, без изменения содержимого
- **Когда** выполняется попиксельное сравнение страниц
- **То** страницы признаются неизменными

#### Scenario: Изменение одного символа
- **Дано** две версии страницы, различающиеся одной изменённой цифрой
- **Когда** выполняется попиксельное сравнение страниц
- **То** страницы признаются изменёнными

#### Scenario: Наклон скана
- **Дано** две версии страницы, повёрнутые относительно друг друга на 1 градус
- **Когда** выполняется попиксельное сравнение страниц
- **То** страницы признаются неизменными

### Requirement: Выравнивание страниц двух документов
Система SHALL выстраивать соответствие между страницами двух документов на
основе попиксельного сравнения. Выравнивание MUST давать три вида страниц:
изменённые пары страниц, страницы, присутствующие только в файле 1, и
страницы, присутствующие только в файле 2. Вставка или удаление страницы
MUST определяться как отдельное событие, а MUST NOT приводить к признанию
прочих страниц изменёнными. Номера страниц MUST использоваться только как
метаданные для отображения и MUST NOT быть входом текстового сравнения.

#### Scenario: Одинаковая разбивка
- **Дано** два документа по 3 страницы с совпадающими страницами 1, 2 и 3
- **Когда** выполняется выравнивание страниц
- **То** получено три изменённые пары страниц без вставок и удалений

#### Scenario: Вставка страницы в середину
- **Дано** в файле 2 между страницами 2 и 3 вставлена новая страница
- **Когда** выполняется выравнивание страниц
- **То** страницы 1, 2 и исходная 3 сопоставлены попарно
- **И** новая страница определена как присутствующая только в файле 2

#### Scenario: Разное число страниц
- **Дано** файл 1 содержит 5 страниц, файл 2 — 2 страницы
- **Когда** выполняется выравнивание страниц
- **То** страницы присутствуют как изменённые пары и как страницы только одного из файлов

#### Scenario: Номера страниц не влияют на сравнение
- **Дано** документы идентичны по содержимому, но во втором файле пронумерованы иначе
- **Когда** выполняется выравнивание и текстовое сравнение
- **То** выравнивание определяет совпадение страниц по содержимому, а не по номеру

### Requirement: Пропуск чтения неизменённых страниц
Страница, признанная при выравнивании неизменной, MUST NOT отправляться
на чтение моделью, а её блоки MUST считаться совпадающими на обеих сторонах.
Если все страницы обоих документов признаны неизменными, ни одна страница
MUST не отправляться на чтение моделью. Изменённые пары страниц MUST
читаться с обеих сторон, а страницы, присутствующие только в одном файле, —
с единственной стороны.

#### Scenario: Неизменённая страница
- **Дано** страница 4 признана неизменной при выравнивании
- **Когда** выполняется конвертация документов
- **То** страница 4 не отправляется на чтение моделью
- **И** её содержимое считается совпадающим на обеих сторонах

#### Scenario: Документы идентичны
- **Дано** все страницы двух документов признаны неизменными
- **Когда** выполняется конвертация документов
- **То** ни одна страница не отправляется на чтение моделью

#### Scenario: Страница только одного файла
- **Дано** страница присутствует только в файле 2 и признана изменённой
- **Когда** выполняется конвертация документов
- **То** на чтение отправляется только страница файла 2

### Requirement: Кропы визуально изменённых областей
Для страниц, признанных изменёнными, система SHALL извлекать изображения
визуально изменённых областей страницы — ограниченных прямоугольников,
покрывающих крупные области различий. Мелкие области, порождённые шумом
сканирования, MUST отбрасываться. Кропы MUST передаваться как изображения
(data-URI) в составе результата сравнения. Суммарный объём кропов одного
документа MUST ограничиваться настраиваемым лимитом; при превышении лимита
кропы MUST отбрасываться по убыванию площади, при этом текст блоков и
вычисление различий MUST NOT изменяться, а результат MUST содержать признак
усечения кропов. Кропы страницы MUST привязываться к странице, а не к
конкретной строке блоков, если точная привязка к строке недоступна.

#### Scenario: Кроп изменённой области
- **Дано** на странице изменён один абзац
- **Когда** извлекаются кропы изменённых областей
- **То** возвращён кроп, покрывающий изменённый абзац

#### Scenario: Кропы шума отбрасываются
- **Дано** страницы различаются только шумом сканирования и признаны изменёнными порогом предобработки
- **Когда** извлекаются кропы
- **То** мелкие области различий отброшены
- **И** либо возвращён один крупный кроп, либо ни одного

#### Scenario: Превышение лимита кропов
- **Дано** суммарный объём кропов документа превышает настроенный лимит
- **Когда** формируется результат сравнения
- **То** кропы отброшены по убыванию площади до уклада в лимит
- **И** результат содержит признак усечения кропов
- **И** текст блоков и вычисление различий не изменились
