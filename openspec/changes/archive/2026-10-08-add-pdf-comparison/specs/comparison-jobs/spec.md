## ADDED Requirements

### Requirement: Парная конвертация PDF
Пайплайн сравнения двух PDF-файлов SHALL выполнять конвертацию парной
функцией, принимающей оба пути: выбор страниц для чтения, выравнивание
страниц и кропы требуют обоих документов. Сравнение файлов других
форматов SHALL выполняться пофайловой конвертацией без изменений.
Результат парной конвертации MUST включать блоки обеих сторон,
выравнивание страниц, кропы и признак усечения кропов.

#### Scenario: Два PDF конвертируются совместно
- **Дано** сравниваются два сканированных PDF
- **Когда** выполняется конвертация
- **То** конвертация выполнена одной функцией, получившей оба пути
- **И** результат содержит блоки обеих сторон и выравнивание страниц

#### Scenario: Сравнение .docx не меняется
- **Дано** сравниваются два файла `.docx`
- **Когда** выполняется конвертация
- **То** каждая сторона конвертируется пофайловой функцией
- **И** модель для чтения страниц не используется

#### Scenario: Признак усечения кропов в результате
- **Дано** кропы превысили настроенный лимит
- **Когда** формируется результат задачи
- **То** результат содержит признак усечения кропов

### Requirement: Передача модели в конвертацию
Пайплайн сравнения SHALL передавать модель в конвертацию документов
явным аргументом. Конвертация файлов, не требующих чтения страниц моделью,
MUST игнорировать переданную модель. Способ получения модели MUST позволять
подмену её тестовым моком без обращения к сети.

#### Scenario: Сканы читаются переданной моделью
- **Дано** сравниваются два сканированных PDF
- **Когда** выполняется конвертация
- **То** чтение страниц выполняется переданной моделью

#### Scenario: Конвертация .docx игнорирует модель
- **Дано** сравниваются два файла `.docx`
- **Когда** выполняется конвертация
- **То** модель не вызывается

#### Scenario: Подмена модели в тестах
- **Дано** в конфигурации задана тестовая модель
- **Когда** выполняется сравнение сканированных документов
- **То** чтение страниц выполняется тестовой моделью без обращения к сети

### Requirement: Выравнивание страниц в результате задачи
Результат завершённой задачи сравнения для PDF-документов MUST содержать
выравнивание страниц двух документов: список изменённых пар страниц, список
страниц только первого файла и список страниц только второго файла. Строки
результата MUST содержать номер страницы своей стороны. Результат MUST
содержать признак наличия визуальных различий между документами и признак
деградации, если чтение части страниц завершилось неудачей.

#### Scenario: Результат со сканированными документами
- **Дано** задача сравнения двух сканированных PDF успешно завершена
- **Когда** клиент запрашивает результат
- **То** результат содержит выравнивание страниц с номерами страниц обеих сторон
- **И** строки результата содержат номера страниц своих сторон

#### Scenario: Выравнивание со вставленной страницей
- **Дано** в файл 2 в середину документа вставлена страница
- **Когда** клиент запрашивает результат
- **То** выравнивание содержит страницу, присутствующую только в файле 2
- **И** прочие страницы сопоставлены по содержимому

#### Scenario: Результат с деградированным чтением
- **Дано** часть страниц не удалось прочитать моделью
- **Когда** клиент запрашивает результат
- **То** результат содержит признак деградации

### Requirement: Прогресс конвертации многостраничных документов
Ответ `GET /api/jobs/<job_id>` MAY содержать необязательное поле прогресса
конвертации с указанием количества обработанных страниц и их общего числа.
Наличие прогресса MUST NOT изменять значения существующих полей ответа,
ключи этапов MUST оставаться прежними. Для документов, не требующих
постраничной обработки, поле прогресса MAY отсутствовать.

#### Scenario: Прогресс при чтении страниц
- **Дано** задача конвертирует сканированный PDF и обработала 12 страниц из 45
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит прогресс «12 из 45»
- **И** ключ этапа остаётся прежним

#### Scenario: Отсутствие прогресса у документа .docx
- **Дано** задача сравнивает два файла `.docx`
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ не содержит поля прогресса

### Requirement: Ограничение объёма кропов в результате
Суммарный объём изображений визуально изменённых областей, передаваемых в
результате задачи, MUST ограничиваться настраиваемым лимитом на документ.
Превышение лимита MUST приводить к отбрасыванию части кропов и к установке
признака усечения кропов в результате. Ограничение кропов MUST NOT влиять на
текст блоков, на вычисление различий и на классификацию фрагментов.

#### Scenario: Кропы укладываются в лимит
- **Дано** суммарный объём кропов документа не превышает настроенный лимит
- **Когда** формируется результат задачи
- **То** все кропы переданы в результате
- **И** признак усечения кропов не установлен

#### Scenario: Кропы превышают лимит
- **Дано** суммарный объём кропов документа превышает настроенный лимит
- **Когда** формируется результат задачи
- **То** часть кропов отброшена, а результат содержит признак усечения кропов
- **И** строки результата и их классы изменений не изменились
