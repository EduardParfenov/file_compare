# Предложение: уточнение replace-фрагментов diff по похожести блоков

> Оформлено задним числом: реализация уже выполнена и влита,
> основная спека `document-diff` синхронизирована.

## Why

При сравнении документов, где подряд идут изменённый, удалённый и добавленный
текст, `difflib` сливает их в один фрагмент `replace` (между ними нет
совпадающих блоков-«якорей»). UI позиционно склеивал старые и новые блоки
такого фрагмента в пары: всё подсвечивалось как «изменено» (зелёный), а при
сдвиге под подсветку попадали и неизменённые блоки. LLM не помогала — ей на
вход уходил весь слипшийся фрагмент. Дополнительно невидимые различия
(неразрывные/двойные пробелы после редактирования в Word) давали ложные
«изменения» в визуально одинаковых абзацах.

## What Changes

- Уточнение replace-фрагментов: внутри каждого `replace` старые и новые блоки
  сопоставляются по похожести текстов (`SequenceMatcher.ratio`, порог 0.6,
  монотонное выравнивание через ДП). Похожие пары остаются `replace`,
  непарные старые блоки становятся `delete`, непарные новые — `insert`.
- Нормализация пробельных символов (включая неразрывные пробелы) при
  разбиении Markdown на блоки — невидимые различия больше не порождают
  ложные изменения.
- Пайплайн задач: `find_diffs` → `refine_fragments` → классификация LLM
  (LLM получает точные мелкие фрагменты и корректно различает
  removed/added); построение выровненных строк без повторного прогона
  `SequenceMatcher`.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `document-diff`: добавлено требование об уточнении replace-фрагментов по
  похожести; требование о разбиении на блоки дополнено нормализацией
  пробельных символов.

## Impact

- **Код**: `app/services/diffing.py` (`refine_fragments`, нормализация в
  `split_blocks`), `app/services/jobs.py` (применение `refine_fragments`,
  упрощённый `_build_rows`).
- **API**: не меняется — формат ответа `GET /api/jobs/<id>` прежний,
  меняется только качество классификации фрагментов.
- **UI**: не меняется — существующая подсветка (зелёный/красный/жёлтый)
  теперь соответствует реальным типам изменений.
- **Производительность**: на патологически больших replace-фрагментах
  уточнение отключается (порог `MAX_REFINE_PAIRS`), отсев непохожих пар
  через `real_quick_ratio`.
- **Тесты**: новые pytest-тесты уточнения фрагментов и нормализации;
  e2e-тест «изменён/удалён/добавлен подряд».
