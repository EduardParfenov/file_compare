# Предложение: опрос статуса задачи каждую секунду

Уровень: исправление

## Why

Клиент опрашивает `GET /api/jobs/<job_id>` раз в 3 секунды, поэтому
результат сравнения и обновления степпера появляются с заметной
задержкой до ~3 с после фактического завершения этапа. Опрос — дешёвый
(in-memory задача, один GET), интервал можно безопасно сократить.

## What Changes

- Интервал опроса статуса задачи сокращается с 3 секунд до 1 секунды
  (`POLL_INTERVAL_MS` в `app/static/app.js`). Первый запрос по-прежнему
  выполняется немедленно после запуска задачи.
- Степпер этапов и его поведение **не меняются**: виден всегда,
  неподсвечен до запуска; активный/завершённые/ошибочные этапы, поведение
  при успехе (все этапы завершены, степпер остаётся) и при ошибке
  (сбойный этап красный + сообщение об ошибке) — как сейчас.
- В `REVIEW.md` обновляется формулировка пункта про «Визуализация
  процесса обработки»: «каждые 3 секунды» → «каждую 1 секунду»
  (покрытие клиентской части тестами по-прежнему отсутствует и в этом
  изменении не добавляется — отложено).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `comparison-jobs`: в требовании «Визуализация процесса обработки на
  клиенте» меняется только интервал опроса: 3 секунды → 1 секунда.
  Остальное поведение (степпер, этапы, успех/ошибка) сохраняется.

## Impact

- Код: `app/static/app.js` (константа `POLL_INTERVAL_MS`: 3000 → 1000).
- Документация: `REVIEW.md` (актуализация интервала в пункте о
  визуализации процесса обработки).
- Спецификации: `openspec/specs/comparison-jobs/spec.md` (MODIFIED
  требование «Визуализация процесса обработки на клиенте»).
- Серверная часть не меняется. Нагрузка на сервер: 1 запрос/с на
  активную задачу вместо 1 запроса/3 с — приемлемо для in-memory
  хранилища задач.
- Тестовое покрытие клиентского опроса/степпера не добавляется
  (осознанно отложено).
