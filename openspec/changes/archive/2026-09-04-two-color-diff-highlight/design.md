# Design: two-color-diff-highlight

## Context

См. proposal.md — Why. `inline_diff` (app/services/diffing.py) внутри
`replace`-фрагментов пословного diff сопоставляет похожие токены
(`_match_pairs` с `SIMILARITY_THRESHOLD`) и помечает их `chg` (жёлтый);
непохожие — `del`/`add`. Fallback изменённого блока — класс
`change-changed` с жёлтым фоном (git-стиль из
`align-block-heights-git-colors`). Маркеры `del-mark`/`add-mark`
(highlight-opposite-word-marks) уже двухцветные. Тот же `_match_pairs`
с порогом используется и на уровне блоков (`_split_replace`) — там он
остаётся.

## Goals / Non-Goals

**Goals:**
- Подсветка различий строго двухцветная: красный (удалено), зелёный
  (добавлено); «изменено» = красное старое + зелёное новое.
- Жёлтый хром интерфейса (рамки, степпер, уведомления) не меняется.

**Non-Goals:**
- Изменение классификации фрагментов (LLM/алгоритм по-прежнему выдают
  label `changed`) и контракта `rows`.
- Изменение `_split_replace` на уровне блоков — отличие изменённых
  блоков от удалённых/добавленных сохраняется.
- Перекраска хрома интерфейса.

## Decisions

### D1: `inline_diff` без `chg`

В `replace`-ветке `inline_diff` убирается `_match_pairs` для токенов:
все старые токены фрагмента — `del` слева, все новые — `add` справа.
Код упрощается до двух вызовов `_append_segment`. Маркеры
`del-mark`/`add-mark` по-прежнему эмитятся только на чистых
`delete`/`insert` opcode'ах — внутри `replace` обе стороны подсвечены.

Следствие: правка части слова (`год`→`года`) теперь показывает всё
слово красным слева и всё слово зелёным справа, а не жёлтые версии —
однозначно по модели git.

Альтернатива: оставить `chg`, но перекрасить в красный/зелёный по
панелям через CSS — отвергнута: понятие «изменённое слово» всё равно
осталось бы в данных и тестах, а семантика «старое/новое» через
цвет панели была бы неявной.

### D2: Fallback изменённого блока — CSS по панелям

Блок с label `changed` без сегментов (пословный diff недоступен)
рендерится с классом `change-changed` на обеих сторонах. Вместо
изменения контракта данных добавляются панельные правила:
`#panel-left .change-changed { background: var(--red-light) }`,
`#panel-right .change-changed { background: var(--green-light) }` —
базовое правило `.change-changed` с жёлтым фоном удаляется. То же для
строк таблиц: `#panel-left tr.change-changed` / `#panel-right
tr.change-changed` (сейчас `change-changed` для строк не задан — строки
с `cell_segments` подсвечиваются пословно; fallback добавляется для
полноты схемы).

Альтернатива: маппить label `changed` в `removed`/`added` по сторонам
на бэкенде — отвергнута: меняет контракт данных ради отображения,
которое решается двумя CSS-правилами.

### D3: Удаление `.seg-chg`

Класс `.seg-chg` удаляется из `style.css` — после D1 сегментов `chg`
не существует. Жёлтые переменные (`--yellow`, `--yellow-light`)
остаются для хрома интерфейса.

## Risks / Trade-offs

- [Правка одной буквы в длинном слове подсветит слово целиком] →
  Приемлемо: так же ведут себя git/GitHub; однозначность важнее
  экономии площади подсветки.
- [Пользователи, привыкшие к жёлтому «изменено» за один день] →
  Осознанное требование пользователя; легенда не требуется — модель
  красный/зелёный общеизвестна.
- [Тесты на `chg` сломаются] → Запланированное обновление:
  `test_similar_replaced_word_marked_chg`,
  `test_letters_inserted_mid_word_marked_chg` переписываются под
  `del`/`add`.
