## Context

Текущее состояние: `_merge_lines` в `pdf_converter.py` соединяет строки
абзаца через `" "`, `_clean` схлопывает все пробельные символы через
`" ".join(text.split())`, а `normalize_blocks` в `diffing.py` делает то же
самое. Из-за этого переносы строк внутри абзаца PDF с текстовым слоем
теряются ещё на этапе конвертации. CSS `white-space: pre-wrap` уже есть в
`style.css`, но не помогает, так как в `text` и `html` нет символов `\n`.
Инвариант `textContent(html) == text` сохраняется за счёт `html.escape`,
ко не трогает `\n`.

## Goals / Non-Goals

**Goals:**
- Сохранить переносы строк внутри абзаца в блоках PDF с текстовым слоем
- Сохранить инвариант `textContent(html) == text` для всех блоков
- Минимальные изменения: не вводить новые поля в контракт блока
- Не менять поведение для `.docx` и для ветки скана (vision OCR)

**Non-Goals:**
- Не изменять ветку чтения страниц моделью (`convert_pdf_by_reading`)
- Не добавлять отдельное поле `display_text` (альтернативный подход)
- Не менять логику сравнения для не-PDF форматов

## Decisions

1. **`_merge_lines` соединяет строки абзаца через `\n` вместо `" "`**
   - Альтернатива: оставить `" "` и добавлять `<br>` в HTML только для отображения
   - Отклонено: нарушило бы инвариант `textContent(html) == text` и потребовало
     нового поля в блоке

2. **`_clean` сохраняет `\n`, схлопывая только прочие пробельные символы**
   - Нужно, потому что `_merge_lines` вызывает `_clean` на итоговом тексте

3. **`normalize_blocks` сохраняет `\n`, схлопывая только прочие пробельные символы**
   - Нужно, иначе `\n` will be destroyed on the way to comparison and API
   - Записано в дельта-спеке `document-diff`

4. **Не вводить новое поле блока (например, `display_text`)**
   - Альтернатива: `text` без `\n` для сравнения, `display_text` с `\n` для отображения
   - Отклонено: ломает предусловие `weaveSegments` (`root.textContent ===
     конкатенация сегментов`), пословный diff стал бы недоступен для PDF с
     переносами

## Risks / Trade-offs

[Документы, отличающиеся только разрывом строк, будут показаны как изменённые] → Допустимо: перенос строк — видимый контент, а не невидимый пробел

[`inline_diff` воспринимает `\n` как токен `\W+`] → Различие в переносах проявится на уровне пословного diff; приемлемо

[Существующие тесты ожидают склеивание абзацев без переносов] → Обновить тесты в `test_pdf_converter.py` и `test_diffing.py`
