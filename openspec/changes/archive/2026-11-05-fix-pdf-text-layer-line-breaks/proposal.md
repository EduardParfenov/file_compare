## Why

При сравнении PDF с текстовым слоем текст в окне сравнения выводится без
переносов строк — единым полотном, не соответствующим формату исходного
файла. Причина: `_merge_lines` склеивает строки абзаца через пробел, а
`_clean` и `normalize_blocks` схлопывают все пробельные символы включая `\n`.
Нужно сохранить переносы строк при отображении, чтобы текст в UI соответствовал
оригинальному PDF.

## What Changes

- `app/services/pdf_converter.py`:
  - `_merge_lines` соединяет строки абзаца через `\n` вместо `" "`
  - `_clean` сохраняет `\n`, схлопывая только прочие пробельные символы
- `app/services/diffing.py`:
  - `normalize_blocks` сохраняет `\n` при нормализации, схлопывая только
    прочие пробельные символы
- CSS `white-space: pre-wrap` уже присутствует в `style.css`, дополнительных
  изменений на клиенте не требуется

## Capabilities

### Modified Capabilities

- `pdf-conversion`: текст блока из PDF с текстовым слоем теперь сохраняет
  переносы строк внутри абзаца; инвариант `textContent(html) == text`
  продолжает выполняться
- `document-diff`: нормализация блоков схлопывает пробельные символы в один
  пробел, но сохраняет символ переноса строки `\n`

## Impact

- Затронуты файлы: `app/services/pdf_converter.py`, `app/services/diffing.py`
- Тесты, ожидающие склеивание абзацев без переносов, потребуют обновления
- Возможны ложные различия, если документы отличаются только разрывом строк
  (при сохранении `\n` в тексте для сравнения)

уровень: исправление
