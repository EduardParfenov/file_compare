# Design: align-block-heights-git-colors

## Context

См. proposal.md — Why. Бэкенд (`jobs.py: _build_rows`) уже выравнивает
строки: удалённому/добавленному блоку соответствует `None` на
противоположной стороне. Фронтенд (`app.js: renderBlock`) рендерит `None`
как `.diff-block.placeholder` фиксированной высоты в одну строку
(`min-height: 1.6em`), а таблицы сторон (`renderTableSide`) строятся
независимо и имеют разную высоту при удалённых/добавленных строках.
Панели одинаковой ширины (`flex: 1`), поэтому переносы строк в парных
блоках совпадают, кроме случаев разного содержимого (изменённые пары).

## Goals / Non-Goals

**Goals:**
- Пиксельно-точное выравнивание высот парных блоков и табличных групп.
- Заглушки цветные: красная напротив удалённого, зелёная напротив
  добавленного; подкладка изменённой пары — нейтральная.
- Единая git-стиль схема фонов: удалено=красный, добавлено=зелёный,
  изменено(fallback)=жёлтый.

**Non-Goals:**
- Изменение бэкенда и структуры данных `rows` — не требуется.
- Изменение пословной подсветки (`seg-*`) — уже git-стиль.
- Изменение хрома интерфейса (рамки, кнопки, степпер) — не входит.
- Синхронизация высот между несмежными блоками — не требуется,
  выравнивание только внутри пары/табличной группы.

## Decisions

### D1: Выравнивание высот после рендера (JS)

После построения обеих панелей выполняется проход по парам дочерних
элементов `content-left`/`content-right` (они строятся синхронно в
`renderResult`, включая табличные группы — один элемент на группу с
каждой стороны). Для каждой пары: сброс `min-height`, измерение
`offsetHeight` обеих сторон, установка обеим `min-height` большего
значения.

Альтернативы:
- Оценка высоты по числу строк (`\n`) — неточна при переносах длинных
  строк, сдвиг сохраняется.
- Общий CSS Grid на обе панели — панели являются отдельными
  прокручиваемыми контейнерами, общий grid невозможен без перестройки
  всей раскладки и отказа от независимого скролла.

Известное ограничение: измерение выполняется один раз после рендера;
при изменении ширины окна переносы строк могут измениться. Панели
одинаковой ширины, поэтому для одинаковых и заглушечных пар высоты
совпадают при любой ширине; для изменённых пар с разной высотой сдвиг
после ресайза теоретически возможен. Ресайз-обработчик с повторным
выравниванием добавляется тривиально (в tasks).

### D2: Тип заглушки по классу изменения противоположной стороны

`renderBlock` получает необязательный параметр `placeholderKind`
(`"removed"` | `"added"`), который вычисляется в `renderResult` из
`change` противоположной стороны строки: у удалённого блока
`change === "removed"` (слева) → заглушка справа `placeholder-removed`;
у добавленного — наоборот. Для табличных групп: если все блоки стороны
`None` (таблица/часть таблицы удалена или добавлена целиком), заглушка
группы получает класс по классу изменения противоположной стороны;
при смешанном составе (часть строк таблицы есть) сторона рендерит свои
строки, а разница высот гасится выравниванием D1.

### D3: Git-стиль цветов через существующие CSS-переменные

Переназначение только фонов, палитра переменных не меняется:
- `.diff-block.change-added`, `.diff-table tr.change-added`:
  `var(--yellow-light)` → `var(--green-light)`
- `.diff-block.change-changed` (fallback): `var(--green-light)` →
  `var(--yellow-light)`
- Новые классы: `.placeholder-removed { background: var(--red-light) }`,
  `.placeholder-added { background: var(--green-light) }`; базовый
  `.placeholder` (серый) остаётся для неопределённых случаев.

Альтернатива: менять значения самих переменных — отвергнута, т.к.
`--yellow-light`/`--green-light` используются и в хроме интерфейса
(степпер, уведомления), который менять нельзя.

## Risks / Trade-offs

- [Повторный рендер при новом сравнении наследует старые min-height] →
  `renderResult` очищает панели (`innerHTML = ""`), выравнивание
  выполняется заново после каждого рендера.
- [Высокие заглушки из пустоты могут выглядеть массивно] → Приемлемо:
  это осознанное требование пользователя, цвет соответствует классу
  изменения.
- [Проход по парам добавляет O(N) измерений layout] → Количество блоков
  в документе умеренное; измерение в одном цикле после рендера, чтения
  и записи сгруппированы, чтобы избежать layout thrashing.
