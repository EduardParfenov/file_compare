# Tasks: table-horizontal-scroll

## 1. Геометрия таблицы (app/static/style.css)

- [x] 1.1 В правиле `.diff-table table` (style.css:274-277) заменить `width: 100%` на `width: max-content; min-width: 100%`: таблица получает естественную ширину по содержимому и растягивается до ширины панели, когда содержимое уже. Проверка: таблица на 3 колонки с короткими значениями по-прежнему занимает всю ширину панели, горизонтальная полоса не появляется.
- [x] 1.2 В правиле `.diff-table td` (style.css:279-284) добавить `min-width: 4em` и `max-width: 40em`. Проверка: на таблице из 14 колонок ни одна колонка не сужена до ширины в одну букву; на ячейке с абзацем текст переносится. Граница сверху (`40em`) относится к ширине, определённой по содержимому: когда таблица растягивается до панели, свободная ширина распределяется между колонками и колонка может стать шире `40em` — тогда таблица не должна требовать горизонтальной прокрутки.
- [x] 1.3 Убрать `overflow-x: auto` из правила `.diff-table` (style.css:269-272): блок таблицы перестаёт быть горизонтальным скролл-контейнером, полосу прокрутки обеспечивает панель. Проверка: в инспекторе вычисленный `overflow-x` у `.diff-table` равен `visible`, у таблицы внутри блока собственной полосы нет.

Примечание к 1.2 (замерено в Chrome, ширина панели → ширина ячейки с абзацем): 579px → 640px (`40em`, таблица шире панели, прокрутка есть); 828px → 717px и 924px → 802px (превышение, но таблица уже панели и прокрутки нет). Поведение зафиксировано в требовании явно двумя сценариями.

Примечание к 1.2: пол `4em` — константа, а не ширина по содержимому ячейки. При `width: max-content` колонка уже получает ширину самой широкой ячейки, поэтому «пол по длине самого длинного слова в заголовке» математически вытесняется этой шириной и не может сработать; константа нужна только для колонок из коротких значений, где и слово-заголовок само по себе узкое.

## 2. Синхронная прокрутка (app/static/app.js)

- [x] 2.1 Добавить защиту от эха в `syncScroll` (app.js:460-476): хранить последнее значение `scrollLeft`, записанное в каждую панель, и игнорировать событие прокрутки, значение которого совпадает с собственной записью. Обоснование: у панелей разный `scrollWidth` (широкие таблицы имеют разную естественную ширину), запись в целевую панель вызывает эхо-событие, которое возвращает источнику обрезанное смещение — панель отскакивает назад у правого края. Проверка: запись значения выполняется один раз, эхо-событие не порождает обратной записи.
- [x] 2.2 Проверить в браузере сценарий разной ширины содержимого: прокрутить панель файла 1 по горизонтали до её максимального смещения — панель файла 2 встаёт на своё максимальное смещение, панель файла 1 не отскакивает назад; смещение передаётся как есть, без масштабирования.
