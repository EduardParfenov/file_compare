# Предложение: сравнение двух версий документов

## Why

Сейчас приложение — только каркас (scaffold): главная страница-заглушка и `/health`.
Пользователю нужен рабочий инструмент: загрузить две версии документа (`.docx`),
увидеть процесс обработки и получить наглядный side-by-side diff с семантической
классификацией каждого изменения (изменено / удалено / добавлено) через
корпоративную LLM.

## What Changes

- Загрузка двух файлов через кнопки «Открыть файл 1/2» и drag-and-drop,
  с валидацией формата (`.docx`) и отдельным эндпоинтом `POST /api/upload`.
- Кнопка «Начать сравнение», активная только после загрузки обоих файлов,
  запускает сравнение через `POST /api/compare` с идентификаторами файлов.
- Асинхронная обработка: задача (job) со статусами этапов
  «Конвертация файлов...» → «Поиск различий...» → «Анализ через LLM...»,
  опрос `GET /api/jobs/<id>` раз в 3 секунды, индикатор загрузки.
- Конвертация `.docx` → Markdown через `python-docx`.
- Гибридный diff: алгоритмический поиск различий по блокам Markdown
  (абзацы, заголовки, строки таблиц) через `difflib`, затем семантическая
  классификация каждого различающегося блока через LLM
  (`langchain-openai`, OpenAI-совместимый API).
- Деградация при сбое LLM: классификация по опкодам difflib с пометкой
  результата «без семантического анализа».
- Diff Viewer: side-by-side панели с синхронным скроллом и подсветкой —
  изменено (зелёный в обоих файлах), удалено (красный в файле 1),
  добавлено (жёлтый в файле 2).
- Новые зависимости: `python-docx` (`.xlsx` через `openpyxl` — вне рамок
  этого change, только точка расширения).

## Capabilities

### New Capabilities

- `file-upload`: загрузка двух файлов через UI (кнопки и drag-and-drop) и
  API `POST /api/upload`, валидация расширения и размера, хранение в
  `UPLOAD_DIR`, активация кнопки «Начать сравнение».
- `markdown-conversion`: конвертация загруженного `.docx` в Markdown
  (абзацы, заголовки, таблицы) как первый этап обработки.
- `document-diff`: разбиение Markdown на блоки и алгоритмический поиск
  различающихся блоков между двумя версиями через `difflib`.
- `llm-classification`: семантическая классификация каждого различающегося
  блока через LLM (changed / removed / added) по строгому JSON-контракту,
  с ретраем и деградацией до классификации по опкодам difflib.
- `comparison-jobs`: асинхронный запуск сравнения, этапные статусы,
  опрос статуса и получение результата через `GET /api/jobs/<id>`.
- `diff-viewer`: отображение результата side-by-side с цветовой подсветкой
  классов изменений и синхронным скроллом панелей.

### Modified Capabilities

(нет — существующих спецификаций в `openspec/specs/` пока нет)

## Impact

- **Код**: новые модули `app/services/` (upload, conversion, diff, llm,
  jobs), расширение `app/routes.py` (API-эндпоинты), новые статические
  файлы `app/static/` (JS/CSS) и доработка `app/templates/index.html`.
- **API**: новые эндпоинты `POST /api/upload`, `POST /api/compare`,
  `GET /api/jobs/<job_id>`. Существующие `GET /` и `GET /health` не меняются.
- **Зависимости**: добавляется `python-docx`; `langchain-openai` уже в
  requirements и начинает реально использоваться.
- **Конфигурация**: используются существующие переменные окружения
  (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `UPLOAD_DIR`,
  `MAX_CONTENT_LENGTH`, `ALLOWED_EXTENSIONS`); новых переменных не требуется.
- **Внешние системы**: корпоративный LLM-сервер
  (`http://172.16.48.122:8002/v1`, OpenAI-совместимый API) — только чтение
  (chat completions); при его недоступности приложение продолжает работать
  в деградированном режиме.
- **Тесты**: новые pytest-тесты с моками LLM (детерминированные, без сети).
