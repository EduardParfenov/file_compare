## Why

Таблицы в PDF с текстовым слоем отображаются не как таблица, а как «сплошняк»: все ячейки строки сливаются в одну ячейку, текст ячеек склеивается без границ. Причина: `_clean` в конвертере PDF схлопывает все múltiчные пробелы в один, а `_table_row_text` ожидает двойные пробелы как разделитель ячеек. После схлопывания двойных пробелов не остаётся, `parse_table_row` возвращает один элемент — всю строку как одну ячейку. Поле `cells` не сохраняется в блоке, поэтому фронтенд не распознаёт строку как табличную и рендерит её как обычный абзац.

## What Changes

- `app/services/pdf_converter.py`:
  - При обнаружении табличной строки (`page.find_tables()`) собирать ячейки по горизонтальным координатам слов (`x0`/`x1`) вместо `text.split("  ")`
  - `build_block` для тега `tr` принимает и сохраняет поле `cells: list[str]` в блоке
  - HTML `<td>...</td>` строится из ячеек как раньше, но теперь `cells` доступен для клиента
- `app/services/diffing.py`:
  - `normalize_blocks` сохраняет поле `cells` при копировании блока (`{**block, "text": text, "cells": cells}`)
- `app/services/jobs.py`:
  - `_row_side` пробрасывает `cells` из конвертерного блока в сторону строки результата
  - `_enrich_table_block` не пере-parсит `cells` из текста, если они уже есть в блоке

## Capabilities

### Modified Capabilities

- `pdf-conversion`: блок строки таблицы PDF теперь содержит структурированное поле `cells` (список текстов ячеек) вместе с текстом и HTML; инвариант `textContent(html) == text` сохраняется
- `document-diff`: нормализация блоков сохраняет поле `cells` без изменений, не пере-parсит из текста

## Impact

- Затронуты файлы: `app/services/pdf_converter.py`, `app/services/diffing.py`, `app/services/jobs.py`
- Фронтенд (`app/static/app.js`, `renderTableSide`, `weaveTableSegments`) уже использует `block.cells` и `block.cell_segments` — дополнительных изменений на клиенте не требуется
- Тесты для конвертера PDF и нормализации потребуют обновления
