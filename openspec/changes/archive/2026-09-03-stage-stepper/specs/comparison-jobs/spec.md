## MODIFIED Requirements

### Requirement: Этапные статусы задачи
Задача сравнения SHALL проходить этапы «Конвертация файлов...» → «Поиск
различий...» → «Анализ через LLM...» и завершаться статусом «готово» либо
«ошибка». Система SHALL предоставлять эндпоинт `GET /api/jobs/<job_id>`,
возвращающий текущий статус задачи, ключ текущего этапа (`stage`:
`converting` / `diffing` / `llm`), сообщение текущего этапа, а при
завершении — результат сравнения (блоки обоих документов и классифицированные
различия) либо сообщение об ошибке. Запрос несуществующей задачи MUST
возвращать код 404.

#### Scenario: Опрос задачи в процессе обработки
- **Дано** задача сравнения запущена и находится на этапе поиска различий
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит статус «в обработке», ключ этапа `diffing` и сообщение «Поиск различий...»

#### Scenario: Получение завершённой задачи
- **Дано** задача сравнения успешно завершена
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит статус «готово»
- **И** результат со структурой обоих документов и классами различий для каждого фрагмента

#### Scenario: Задача завершилась ошибкой
- **Дано** задача сравнения завершилась ошибкой конвертации
- **Когда** клиент запрашивает `GET /api/jobs/<job_id>`
- **То** ответ содержит статус «ошибка» и сообщение об ошибке

#### Scenario: Запрос несуществующей задачи
- **Когда** клиент запрашивает `GET /api/jobs/<несуществующий_id>`
- **То** ответ имеет код 404 и JSON с полем `error`

### Requirement: Визуализация процесса обработки на клиенте
Веб-страница SHALL отображать степпер этапов обработки: шаги
«Конвертация файлов» → «Поиск различий» → «Анализ через LLM» в один ряд,
видимые всегда (до запуска — неподсвеченные). Во время обработки клиент
MUST опрашивать `GET /api/jobs/<job_id>` до финального статуса: первый
запрос — немедленно после запуска, далее — с интервалом 3 секунды.
Текущий этап MUST выделяться как активный, пройденные этапы — как
завершённые; при успехе все этапы отмечаются завершёнными и степпер
остаётся на экране, при ошибке сбойный этап отмечается как ошибочный и
отображается сообщение об ошибке.

#### Scenario: Степпер до запуска сравнения
- **Дано** пользователь открыл страницу и ещё не нажимал «Начать сравнение»
- **Когда** страница отображается
- **То** виден степпер из трёх этапов в неподсвеченном (сером) состоянии

#### Scenario: Отображение этапов во время обработки
- **Дано** пользователь нажал «Начать сравнение» и задача запущена
- **Когда** задача находится на этапе поиска различий
- **То** этап «Конвертация файлов» отмечен завершённым (зелёный)
- **И** этап «Поиск различий» отмечен активным (жёлтый с пульсацией)
- **И** опрос статуса выполняется каждые 3 секунды после немедленного первого запроса

#### Scenario: Успешное завершение обработки
- **Дано** задача сравнения успешно завершена
- **Когда** клиент получает финальный статус
- **То** все этапы степпера отмечены завершёнными (зелёный), степпер остаётся на экране
- **И** отображается результат сравнения

#### Scenario: Завершение обработки с ошибкой
- **Дано** задача сравнения завершилась ошибкой на этапе анализа через LLM
- **Когда** клиент получает финальный статус
- **То** пройденные этапы отмечены завершёнными, сбойный этап — ошибочным (красный)
- **И** отображается сообщение об ошибке
