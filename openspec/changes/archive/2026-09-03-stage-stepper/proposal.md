# Предложение: степпер этапов сравнения вместо спиннера

> Оформлено задним числом: реализация уже выполнена,
> основная спека `comparison-jobs` синхронизирована.

## Why

Два бага индикации прогресса:

1. **Спиннер не останавливался** после завершения: author-стиль
   `.status { display: flex }` переопределял UA-стиль `[hidden]`,
   поэтому `hideStatus()` визуально не скрывал статус-бар (та же проблема
   у `.diff-container` — пустые панели diff были видны до сравнения).
2. **Этапы не показывались**: первый опрос статуса уходил только через
   3 секунды после старта; на небольших файлах задача завершалась быстрее,
   и пользователь не видел этапы «Конвертация файлов...» → «Поиск
   различий...» → «Анализ через LLM...».

## What Changes

- Степпер этапов вместо статус-бара со спиннером: три шага в один ряд,
  всегда виден на странице (до старта — серый). Текущий этап — жёлтый с
  пульсацией, пройденные — зелёные, после `done` — все зелёные (остаётся
  на экране), при `failed` — сбойный этап красный.
- API: `GET /api/jobs/<job_id>` дополнительно возвращает ключ этапа
  `stage` (`converting` / `diffing` / `llm`) — обратносовместимо.
- Первый опрос статуса выполняется немедленно после запуска (интервал
  3 секунды сохраняется) — этапы видны даже на быстрых задачах.
- Глобальный фикс CSS `[hidden] { display: none !important; }` —
  корректное скрытие всех компонентов с атрибутом `hidden`.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `comparison-jobs`: ответ статуса задачи включает ключ этапа `stage`;
  визуализация процесса на клиенте — степпер этапов вместо спиннера.

## Impact

- **Код**: `app/routes.py` (поле `stage`), `app/templates/index.html`
  (разметка степпера), `app/static/app.js` (логика степпера, немедленный
  первый опрос), `app/static/style.css` (стили степпера, фикс `[hidden]`).
- **API**: обратносовместимое расширение ответа `GET /api/jobs/<job_id>`.
- **Тесты**: проверка поля `stage` в ответе статуса; рендер состояний
  степпера — проверка в headless Chrome.
