# Предложение: пословная подсветка внутри изменённых блоков

> Оформлено задним числом: реализация уже выполнена,
> основная спека `diff-viewer` синхронизирована.

## Why

При изменении одного слова в абзаце diff viewer подсвечивал зелёным весь
блок целиком — невозможно увидеть, что именно изменилось. Нужна подсветка
только реально добавленных/изменённых слов внутри изменённого блока.

## What Changes

- Пословный diff внутри изменённой пары блоков: тексты разбиваются на
  токены (слова и не-слова), сравниваются через `difflib.SequenceMatcher`,
  результат — сегменты `{"text", "type"}` для каждой стороны, где
  type: `same` / `add` / `del` / `chg` (похожие версии слова — `chg`,
  непохожие — `del`+`add`).
- API результата: у блоков с `change: "changed"` появляется поле
  `segments` (для патологически длинных блоков — отсутствует).
- Diff viewer: блок с `segments` не заливается фоном целиком —
  подсвечиваются только различающиеся слова в git-стиле: добавленные
  зелёным, удалённые красным, изменённые жёлтым.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `diff-viewer`: требование о цветовой подсветке дополнено пословной
  подсветкой изменённых блоков.

## Impact

- **Код**: `app/services/diffing.py` (`inline_diff`),
  `app/services/jobs.py` (поле `segments` в строках результата),
  `app/static/app.js` (рендер сегментов), `app/static/style.css`
  (стиль `.seg-diff`).
- **API**: обратносовместимое расширение — новое необязательное поле
  `segments` у блоков результата; `text`/`change` сохраняются.
- **Производительность**: пословный diff только для изменённых пар;
  защита от квадратичного перебора (`MAX_INLINE_TOKENS`).
- **Тесты**: unit-тесты `inline_diff`, обновлены e2e-ожидания строк
  результата с `segments`.
