# Proposal: formatted-document-view

## Why

Текущий diff-viewer отображает документы как plain text (markdown-блоки):
при конвертации теряется всё форматирование — жирный/курсив, стили
заголовков, списки, картинки. Для деловых документов (договоры, отчёты)
это критично: пользователь не видит документ «как есть» и хуже
ориентируется в изменениях. Заодно устраняется архитектурный долг:
markdown-строка — лишний промежуточный формат между конвертером и
diff-движком, который усложнит добавление `.pdf` (у PDF нет
естественного markdown-представления).

## What Changes

- **BREAKING**: контракт конвертера меняется с «markdown-строка» на
  «упорядоченный список блоков-объектов» `Block{text, html, images}`:
  - `text` — plain text блока (для diff-движка и LLM, поведение
    сравнения не меняется);
  - `html` — форматированный HTML блока (заголовки, жирный/курсив,
    списки, таблицы) для отображения;
  - `images` — изображения блока (base64 data-URI) с ограничением
    суммарного размера.
- Разбиение документа на блоки переносится из `split_blocks` (diffing)
  в конвертер; за diff-движком остаётся нормализация пробельных
  символов. Гранулярность блоков не меняется: заголовок, абзац, строка
  таблицы.
- Diff-viewer рендерит `html` блоков вместо plain text: стилизованные
  заголовки, форматирование текста, HTML-таблицы, картинки.
- Пословный diff (seg-спаны) вплетается в текстовые узлы HTML блоков,
  не ломая разметку; при невозможности — fallback на текущее
  plain text отображение.
- Палитра и двухцветная модель подсветки (красный/зелёный, без жёлтого)
  не меняются.
- Изображения из `.docx` извлекаются и отображаются в панелях; удалённые
  и добавленные картинки подсвечиваются наравне с текстовыми блоками.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `markdown-conversion`: контракт конвертации меняется с выдачи
  Markdown-строки на выдачу упорядоченного списка блоков-объектов
  `{text, html, images}`; требования к таблицам, детерминированности и
  обработке ошибок сохраняются на уровне блоков; добавляются требования
  к HTML-представлению и извлечению изображений.
- `document-diff`: требование «Разбиение Markdown на блоки» заменяется
  требованием нормализации текстовых блоков (разбиение — обязанность
  конвертера); алгоритм поиска и уточнения фрагментов не меняются.
- `diff-viewer`: отображение форматированного HTML блоков и изображений
  с сохранением выравнивания, синхронной прокрутки и двухцветной
  подсветки; вплетение пословного diff в HTML.

уровень: несовместимое поведение

## Impact

- **Код**: `app/services/docx_converter.py` (генерация блоков
  text/html/images), `app/services/conversion.py` (контракт),
  `app/services/diffing.py` (split_blocks → нормализация блоков),
  `app/services/jobs.py` (rows с html/images), `app/static/app.js`
  (рендер HTML, walker для seg-спанов), `app/static/style.css`
  (стили документа), `tests/` (конвертация, diffing, jobs, viewer
  через API).
- **API**: элементы `rows[]` в результате задачи получают поля
  `html`/`images`; `text` сохраняется.
- **Зависимости**: новых нет (python-docx уже предоставляет runs и
  изображения).
- **Конвенции**: docker-friendly сохраняется, LibreOffice и внешние
  конвертеры не вводятся.
- **Не входит в объём**: постраничный вид «как на печать» (docx→PDF),
  поддержка `.pdf`/`.xlsx`, «просмотр оригинала» отдельным режимом.
