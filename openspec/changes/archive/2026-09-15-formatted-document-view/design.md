# Design: formatted-document-view

## Context

Мотивация — в proposal.md. Текущее состояние: конвертер возвращает
markdown-строку, `split_blocks` (diffing) разбивает её на текстовые
блоки, viewer рендерит `textContent` и собирает таблицы из `|`-строк.
Diff-ядро (`find_diffs`, `refine_fragments`, `inline_diff`) работает на
списках строк и формат-агностично — его не трогаем. LLM получает plain
text — не трогаем. Ограничения: docker-friendly, без новых зависимостей,
vanilla JS без сборки, конфигурация через env.

## Goals / Non-Goals

**Goals:**

- Контракт конвертера: `list[Block]`, `Block = {"text": str, "html": str, "images": list[str]}`.
- Форматированный рендер блоков (заголовки, bold/italic/underline,
  списки, таблицы) с сохранением всей модели подсветки.
- Изображения из docx в панелях, с подсветкой добавленных/удалённых.
- Контракт готов к будущему `.pdf`-конвертеру (`html`/`images` могут
  быть пустыми — viewer деградирует к plain text).

**Non-Goals:**

- Постраничный вид «как на печать», docx→PDF, LibreOffice.
- Наследование форматирования из стилей/темы docx (только прямые
  атрибуты runs: `bold`, `italic`, `underline`; `None` = нет
  форматирования). Разрешение стилей — отдельное изменение, если
  понадобится.
- Diff по не-tекстовым свойствам (цвет, шрифт, отступы): изменение
  только форматирования без изменения текста НЕ детектируется.
- Нумерация `ol` с учётом docx-нумерации (списки рендерятся простыми
  `ul`/`ol`).

## Decisions

### D1. Блок — словарь, текст таблицы сохраняет `|`-формат

`Block.text` для строк таблиц остаётся markdown-подобной строкой
`| a | b |`: существующие `is_table_row`/`parse_table_row` и группировка
таблиц во viewer продолжают работать без изменений, diff-поведение
таблиц (включая cell_segments) не меняется. Служебная строка-разделитель
`| --- |` конвертером более НЕ эмитится: она была нужна только
markdown-представлению, а viewer собирает таблицу из `<td>`-фрагментов
(см. D3); соответствующие проверки (`is_table_separator`) остаются
безвредными. Альтернатива (структурные `cells` в блоке) — чище, но
ломает diffing/jobs без выигрыша на этом этапе.

### D2. HTML генерируется конвертером, безопасность — на этапе генерации

`docx_converter` строит HTML сам: текст runs экранируется
(`html.escape`), порождается фиксированный набор тегов (`h1`–`h6`, `p`,
`strong`, `em`, `u`, `ul`, `ol`, `li`, `td`). Никакой разметки из
содержимого документа. Поэтому viewer может вставлять HTML через
`innerHTML` без санитайзера — доверяем только собственной генерации;
это фиксируется комментарием в коде. Альтернатива (клиентский
санитайзер/whitelist) — лишний код при единственном источнике HTML.

### D3. HTML строки таблицы — фрагмент `<td>…</td>…`

Viewer группирует подряд идущие табличные блоки в `<table>` (как
сейчас), каждый блок — `<tr>`, в который вставляется td-фрагмент.
Порядок `<td>` соответствует `cells`, поэтому пословный diff ячеек
(`cell_segments[c]`) вплетается в c-й `<td>` тем же walker'ом, что и для
текстовых блоков. Ячейки без форматирования получают `<td>` с
экранированным текстом — поведение вырождается в текущее.

### D4. Пословный diff вплетается walker'ом на клиенте

`weaveSegments(el, segments)`: обход text nodes в порядке документа с
накоплением смещений; сегменты `del`/`add` — текстовые узлы режутся
(`splitText`) по границам и оборачиваются в `span.seg-*`; `del-mark`/
`add-mark` (пустые) — вставка узкой метки в позицию. Контракт:
`textContent` блока обязан совпадать с `text` (конвертер строит оба из
одних runs); перед вплетением viewer проверяет совпадение — при
расхождении fallback на текущий plain text рендер с сегментами.
Альтернатива (вплетение на сервере в jobs.py) — смешивает слои и
дублирует walker на Python; отклонена.

### D5. Изображения: извлечение в конвертере, сравнение в jobs

Конвертер: обход runs абзаца, `a:blip` → `rId` →
`document.part.related_parts[rId]` → `{data_uri, sha1}` в `images`
блока (в порядке следования; нечитаемые пропускаются). Лимит суммарного
размера декодированных изображений на документ — env
`MAX_IMAGES_TOTAL_BYTES` (по умолчанию 10 МБ), сверх лимита — отброс с
хвоста.

Текст блока изображения не содержит → текстовый diff «не видит» замену
картинки при том же тексте. Поэтому в `jobs._build_rows` для парных
блоков (equal и changed) сравниваются списки sha1: при расхождении
блок помечается `images_changed`, viewer рисует красную рамку слева и
зелёную справа. Удалённые/добавленные блоки подсвечиваются существующей
моделью — рамка изображения наследует change-класс блока. В LLM
изображения не уходят.

### D6. split_blocks → normalize_blocks

`diffing.split_blocks(str)` заменяется на
`normalize_blocks(blocks) -> list[Block]`: сворачивание пробельных
символов (включая NBSP) в `text` каждого блока, отброс ставших пустыми.
`jobs` передаёт в `find_diffs` списки текстов; rows строятся по блокам
(индексы совпадают). Поведение сравнения идентично текущему — это
фиксируется существующими тестами diffing/jobs (обновлёнными под
новый интерфейс).

### D7. Выравнивание высот — после загрузки изображений

`equalizeHeights` дополнительно вызывается по `load` каждого `<img>`
(через `capture`-слушатель на контейнере) — иначе панели разъезжаются
после догрузки картинок. CSS: `img { max-width: 100%; height: auto; }`.

## Risks / Trade-offs

- [HTML-инъекция через содержимое docx] → экранирование текста и
  фиксированный набор тегов в конвертере (D2); тест со `<script>` в
  тексте.
- [Расхождение `textContent` и `text` ломает вплетение] → проверка
  перед вплетением + fallback на plain text (D4); конвертер строит оба
  представления из одних runs.
- [Раздувание JSON результата base64-картинками] → лимит
  `MAX_IMAGES_TOTAL_BYTES`; отброс с хвоста; документ с картинками >
  лимита всё равно сравнивается по тексту.
- [Замена картинки при неизменном тексте не видна diff-ядру] →
  сравнение sha1 в jobs (D5); компромисс: изображения не участвуют в
  семантической классификации.
- [Наследуемое из стилей форматирование не отображается] → осознанное
  ограничение (Non-Goals), зафиксировано в REVIEW.md после
  реализации.

## Migration Plan

Обратной несовместимости для пользователей нет (веб-интерфейс, нет
внешних потребителей API). Порядок: контракт блоков + конвертер →
diffing/jobs → viewer → стили. После каждого шага `pytest`. Откат —
git revert change'а целиком. Обновить `.env.example`
(`MAX_IMAGES_TOTAL_BYTES`), `README.md` (описание отображения),
`REVIEW.md` (соответствие спекам).
