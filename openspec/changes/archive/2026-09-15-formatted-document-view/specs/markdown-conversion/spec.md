## REMOVED Requirements

### Requirement: Конвертация .docx в Markdown
**Reason**: Контракт конвертера меняется с Markdown-строки на
упорядоченный список блоков-объектов `{text, html, images}` — это даёт
форматированный вид и устраняет markdown-прослойку, неестественную для
будущих форматов (`.pdf`).
**Migration**: Потребители (diff-движок, LLM) используют поле `text`
блоков; отображение использует `html` и `images`. Правила формирования
текста таблиц (flatten, экранирование, сворачивание пробелов)
сохраняются в новом требовании «Конвертация .docx в блоки документа».

## ADDED Requirements

### Requirement: Конвертация .docx в блоки документа
Система SHALL конвертировать `.docx`-файл в упорядоченный список
блоков-объектов. Каждый блок MUST содержать: текст (plain text для
сравнения и LLM), HTML-представление (для отображения) и список
изображений (может быть пустым). Блоками являются заголовки, абзацы и
строки таблиц в порядке следования в документе. Текст блока MUST
формироваться по прежним правилам: переносы строк и множественные
пробелы внутри ячейки таблицы MUST сворачиваться в один пробел; символ
`|` внутри ячейки MUST экранироваться как `\|`; объединённые ячейки
(horizontal/vertical merge) MUST эмитироваться в расплющенном (flatten)
виде: текст — один раз в первой позиции, повторные виртуальные ячейки —
пустыми, с сохранением числа колонок таблицы. Служебная строка-
разделитель Markdown-таблицы (`| --- |`) MUST NOT эмититься: она была
артефактом markdown-представления и блоком документа не является. Пустые
абзацы MUST пропускаться. Конвертация MUST быть детерминированной: один и тот же
входной файл даёт одинаковый список блоков. Повреждённый файл MUST
давать ошибку конвертации с понятным сообщением.

#### Scenario: Документ с заголовком и абзацем
- **Дано** загружен `.docx` с заголовком 1-го уровня «Отчёт» и абзацем «Текст отчёта»
- **Когда** выполняется конвертация
- **То** результат — два блока в порядке следования: заголовок с текстом «Отчёт» и абзац «Текст отчёта»
- **И** каждый блок содержит текст, HTML-представление и список изображений

#### Scenario: Таблица с объединёнными ячейками
- **Дано** загружен `.docx` с таблицей, содержащей горизонтально и вертикально объединённые ячейки
- **Когда** выполняется конвертация
- **То** текст каждой объединённой ячейки присутствует в тексте блоков-строк один раз, повторные виртуальные ячейки пустые
- **И** число колонок во всех строках таблицы сохраняется

#### Scenario: Ячейка таблицы с символом пайпа
- **Дано** загружен `.docx` с таблицей, ячейка которой содержит символ `|`
- **Когда** выполняется конвертация
- **То** в тексте блока-строки символ `|` внутри ячейки экранирован как `\|`

#### Scenario: Пустой документ
- **Дано** загружен `.docx` без содержимого
- **Когда** выполняется конвертация
- **То** результат — пустой список блоков, ошибки не возникает

#### Scenario: Детерминированность
- **Дано** один и тот же `.docx` файл
- **Когда** конвертация выполняется дважды
- **То** оба результата идентичны (текст, HTML, изображения)

#### Scenario: Повреждённый файл
- **Дано** загружен файл с расширением `.docx`, не являющийся валидным DOCX
- **Когда** выполняется конвертация
- **То** возникает ошибка конвертации с понятным сообщением
- **И** задача сравнения завершается со статусом ошибки

### Requirement: HTML-представление блоков
HTML каждого блока MUST отражать форматирование документа: заголовки —
теги `<h1>`–`<h6>` по уровню стиля; выделение текста (жирный, курсив,
подчёркнутый) — inline-теги; списки — маркированные/нумерованные
элементы; строки таблиц — последовательность ячеек строки. Текстовое
содержимое MUST экранироваться, чтобы разметка из документа не могла
попасть в HTML (защита от HTML-инъекций через содержимое документа).
Набор порождаемых тегов и атрибутов MUST быть ограничен фиксированным
безопасным списком: без скриптов, без обработчиков событий, без ссылок
на внешние ресурсы. HTML MUST быть детерминированным.

#### Scenario: Жирный текст в абзаце
- **Дано** в `.docx` абзац содержит слово, выделенное жирным
- **Когда** выполняется конвертация
- **То** HTML блока содержит это слово, обёрнутое в тег жирного выделения
- **И** текст блока содержит то же слово без разметки

#### Scenario: Экранирование разметки из документа
- **Дано** в `.docx` абзац содержит текст `<script>alert(1)</script>`
- **Когда** выполняется конвертация
- **То** HTML блока содержит этот текст в экранированном виде
- **И** HTML не содержит исполняемой разметки из содержимого документа

#### Scenario: Уровень заголовка
- **Дано** в `.docx` заголовок 3-го уровня
- **Когда** выполняется конвертация
- **То** HTML блока использует тег `<h3>`

### Requirement: Извлечение изображений
Изображения, встречающиеся в `.docx`, MUST извлекаться и включаться в
блоки в порядке следования в документе как data-URI (base64).
Суммарный размер изображений документа MUST ограничиваться лимитом,
настраиваемым через переменную окружения; при превышении лимита
изображения сверх лимита MUST отбрасываться в порядке следования, при
этом текстовое и HTML-содержимое блоков MUST NOT изменяться.
Повреждённые или нечитаемые изображения MUST пропускаться без ошибки
конвертации.

#### Scenario: Изображение в абзаце
- **Дано** в `.docx` абзац содержит изображение
- **Когда** выполняется конвертация
- **То** блок этого абзаца содержит изображение как data-URI

#### Scenario: Превышение лимита изображений
- **Дано** в `.docx` суммарный размер изображений превышает настроенный лимит
- **Когда** выполняется конвертация
- **То** изображения сверх лимита отброшены в порядке следования
- **И** текст и HTML блоков не изменились

#### Scenario: Нечитаемое изображение
- **Дано** в `.docx` содержится повреждённое изображение
- **Когда** выполняется конвертация
- **То** изображение пропущено, конвертация завершается успешно
