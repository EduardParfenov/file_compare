## Purpose

Автоматический конвейер непрерывной интеграции (GitHub Actions), прогоняющий
проверки качества и безопасности на каждое изменение кода проекта.

## ADDED Requirements

### Requirement: Триггеры конвейера
Конвейер CI SHALL запускаться на событие push в ветку master и на событие
pull_request.

#### Scenario: Push в master
- **WHEN** выполняется push в ветку master
- **THEN** конвейер CI запускается

#### Scenario: Pull request
- **WHEN** создаётся или обновляется pull request
- **THEN** конвейер CI запускается

### Requirement: Порядок и состав шагов
Конвейер CI SHALL выполнять шаги строго в порядке: проверка форматирования
(ruff format --check .), линтер (ruff check .), тесты (pytest), поиск секретов
(gitleaks), аудит уязвимостей зависимостей (pip-audit по requirements.txt и
requirements-dev.txt), валидация спецификаций (openspec validate --all
--strict — в неинтерактивном режиме без --all команда ничего не проверяет).
Шаги проверки типов (mypy) и сборки в конвейер MUST NOT включаться.

#### Scenario: Порядок шагов соблюдён
- **WHEN** конвейер CI запущен
- **THEN** шаги выполняются в заданном порядке: форматирование, линтер,
  тесты, секреты, аудит зависимостей, валидация спецификаций

### Requirement: Остановка на первом падении
Конвейер CI SHALL останавливать прогон на первом упавшем шаге
(поведение по умолчанию MUST NOT отключаться).

#### Scenario: Шаг упал
- **WHEN** какой-либо шаг конвейера завершается с ошибкой
- **THEN** последующие шаги не выполняются, а прогон помечается failed

### Requirement: Закреплённые рантаймы и кеширование
Конвейер CI SHALL использовать закреплённый Python 3.11 с кешированием pip,
а Node.js закреплённой версии SHALL настраиваться отдельным шагом только
для валидации спецификаций.

#### Scenario: Окружение прогона
- **WHEN** конвейер CI запущен
- **THEN** используется Python 3.11 с кешем pip, а Node.js настраивается
  отдельным шагом перед валидацией спецификаций

### Requirement: Зависимости для тестов и инструментов
Dev-зависимости (pytest, ruff, pip-audit) SHALL быть закреплены в
requirements-dev.txt, а конвейер SHALL устанавливать зависимости одним шагом
из requirements.txt и requirements-dev.txt.

#### Scenario: Установка зависимостей
- **WHEN** конвейер CI устанавливает зависимости
- **THEN** выполняется установка из requirements.txt и requirements-dev.txt
  с закреплёнными версиями

### Requirement: Тесты без реальной LLM
Тесты в CI MUST NOT обращаться к реальной LLM или внешней сети; взаимодействие
с LLM SHALL мокаться.

#### Scenario: Прогон тестов в раннере
- **WHEN** шаг тестов выполняется в раннере CI без доступа к LLM
- **THEN** все тесты проходят на моках без сетевых вызовов к LLM
