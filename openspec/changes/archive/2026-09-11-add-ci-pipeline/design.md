# Design: add-ci-pipeline

## Context

См. proposal.md — Why. В репозитории нет `.github/`; тесты (95 шт.) проходят
локально с моком LLM, сеть не используется. Ветка по умолчанию — `master`
(ветки `main` нет). Dev-инструменты (pytest, ruff, pip-audit) ранее не были
зафиксированы в requirements-файлах.

## Goals / Non-Goals

Goals:
- Один workflow `.github/workflows/ci.yml`, воспроизводимый локально шаг за
  шагом (те же команды, что описаны в AGENTS.md/README).
- Закреплённые версии рантаймов и dev-зависимостей.

Non-Goals:
- Исправление существующих нарушений ruff (отдельный change).
- Кеширование npm (нет package.json; npx тянет openspec на каждый прогон).
- Матрица версий ОС/Python, проверка типов, сборка, деплой.

## Decisions

- **Один job вместо нескольких параллельных.** Требуется строгий порядок
  шагов и остановка на первом падении — в одном job это поведение GitHub
  Actions по умолчанию (`if: success()`), ничего отключать не нужно.
  Альтернатива (job на каждую проверку) нарушила бы «стоп на первом падении»
  и дублировала setup.
- **gitleaks/gitleaks-action@v2** вместо ручной установки бинарника —
  официальный action, закреплённая мажорная версия; для личного
  репозитория лицензия не требуется.
- **requirements-dev.txt** (pytest, ruff, pip-audit; версии из `pip freeze`
  локального .venv) — версии инструментов воспроизводимы локально и в CI;
  установка одним шагом `pip install -r requirements.txt
  -r requirements-dev.txt`. Альтернатива (inline `pip install ruff
  pip-audit` в шагах) отклонена: версии плывут, локальная воспроизводимость
  хуже.
- **Python 3.11 + `cache: pip`** в `actions/setup-python@v5`; кеш ключуется
  по requirements-файлам автоматически.
- **Node.js 22 отдельным шагом** непосредственно перед `npx openspec
  validate --all --strict` — Node нужен только для openspec CLI; кеш npm не
  включаем (нет lock-файла). Флаг `--all` обязателен: в неинтерактивном
  режиме `openspec validate --strict` без аргументов ничего не проверяет
  («Nothing to validate»), шаг проходил бы вхолостую.
- **Push-триггер только на `master`** — ветки `main` не существует;
  `pull_request` — на любые целевые ветки.
- **BLE001 в `app/services/llm.py` — осознанный `# noqa`**, а не сужение
  `except`: контракт `classify_fragment` — «любой сбой chat-модели (сеть,
  API, таймаут) → фолбэк-метка». Сужение до конкретных классов исключений
  изменило бы поведение деградации в проде; noqa с комментарием-обоснованием
  фиксирует намерение.
- **TRY004 в `app/__init__.py`**: `ValueError` → `TypeError` для случая
  «LLM_EXTRA_BODY — не JSON-объект». Путь тестами не покрыт; покрытый
  тестами случай невалидного JSON остаётся `ValueError`.
- **PLW1508**: дефолт `os.environ.get("MAX_CONTENT_LENGTH", ...)` приведён
  к `str(...)` — семантика (16 МиБ) не изменилась.
- **RUF012/SIM115 в тестах**: `ClassVar` для `CONFIG`; `Path.read_bytes()`
  вместо `open(...).read()`.

## Risks / Trade-offs

- [gitleaks-action для организаций требует лицензию] → репозиторий личный;
  при переносе в организацию заменить на установку бинарника.
- [`npx openspec` тянет CLI при каждом прогоне] → приемлемо (один пакет);
  при росте времени прогона закрепить версию openspec и включить кеш npm.
- [`# noqa: BLE001` скрывает правило точечно] → комментарий рядом
  объясняет намерение; при появлении типизированных исключений SDK можно
  сузить catch отдельным change'ом.

## Migration Plan

Миграции нет: добавляются `.github/workflows/ci.yml` и
`requirements-dev.txt`, правки кода — стилевые. Откат — revert коммита.
После исправления находок ruff первый прогон CI ожидаемо зелёный.
