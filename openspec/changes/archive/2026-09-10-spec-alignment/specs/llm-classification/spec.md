# llm-classification Delta

## ADDED Requirements

### Requirement: Дополнительные параметры запроса к LLM
Система SHALL поддерживать конфигурацию `LLM_EXTRA_BODY` — JSON-объект из
переменной окружения, пробрасываемый в тело каждого запроса к LLM
(`extra_body` клиента OpenAI-совместимого API), например для отключения
режима thinking у Qwen3
(`{"chat_template_kwargs": {"enable_thinking": false}}`). Пустое значение
MUST означать отсутствие дополнительных параметров. Невалидный JSON или
JSON, не являющийся объектом, MUST приводить к fail-fast ошибке при
создании приложения. Таймаут запроса к LLM MUST быть ограничен; текущее
значение — 30 секунд (предварительное).

#### Scenario: Проброс дополнительных параметров
- **Дано** в окружении задан `LLM_EXTRA_BODY` со значением `{"chat_template_kwargs": {"enable_thinking": false}}`
- **Когда** создаётся приложение и chat-модель
- **То** запросы к LLM содержат эти дополнительные параметры тела

#### Scenario: Невалидный LLM_EXTRA_BODY
- **Дано** в окружении задан `LLM_EXTRA_BODY` с невалидным JSON
- **Когда** создаётся приложение
- **То** приложение не запускается: ошибка конфигурации возникает сразу (fail fast)

## MODIFIED Requirements

### Requirement: Классификация блока через LLM
Система SHALL отправлять каждый различающийся фрагмент в LLM
(OpenAI-совместимый chat completions API, адрес из `LLM_BASE_URL`, модель
из `LLM_MODEL`) с системным промптом-классификатором на русском языке.
Ответ LLM MUST быть строгим JSON вида `{"label": "changed" | "removed" |
"added"}`. Система MUST парсить и валидировать ответ; значение вне
допустимого множества считается некорректным. Как допустимый fallback
система SHALL извлекать метку из первого JSON-объекта `{...}` в
произвольном тексте ответа (модель может оборачивать JSON в пояснения).

#### Scenario: Блок классифицирован как изменённый
- **Дано** LLM доступна и возвращает `{"label": "changed"}` для фрагмента
- **Когда** выполняется семантическая классификация фрагмента
- **То** фрагмент получает класс «изменено» с признаком семантического анализа

#### Scenario: Блок классифицирован как удалённый или добавленный
- **Дано** LLM доступна и возвращает `{"label": "removed"}` или `{"label": "added"}`
- **Когда** выполняется семантическая классификация фрагмента
- **То** фрагмент получает класс «удалено» или «добавлено» соответственно

#### Scenario: JSON обёрнут в произвольный текст
- **Дано** LLM вернула текст `Ответ: {"label": "changed"} спасибо`
- **Когда** выполняется семантическая классификация фрагмента
- **То** метка извлекается из первого JSON-объекта в тексте
- **И** фрагмент получает класс «изменено» с признаком семантического анализа

### Requirement: Валидация ответа и повторная попытка
При некорректном ответе LLM (невалидный JSON или недопустимое значение
`label`) система SHALL выполнить ровно одну повторную попытку запроса.
Повторная попытка MUST выполняться только при некорректном ответе: при
ошибке соединения, таймауте или ошибке API повторная попытка MUST NOT
выполняться — система сразу переходит к деградированной классификации.
Если и повторный ответ некорректен, система MUST перейти к деградированной
классификации по опкоду difflib.

#### Scenario: Ретрай после некорректного ответа
- **Дано** первый ответ LLM — не JSON, а повторный — `{"label": "changed"}`
- **Когда** выполняется семантическая классификация фрагмента
- **То** отправлено ровно два запроса к LLM
- **И** фрагмент получает класс «изменено» с признаком семантического анализа

#### Scenario: Оба ответа некорректны
- **Дано** оба ответа LLM некорректны
- **Когда** выполняется семантическая классификация фрагмента с операцией `replace`
- **То** фрагмент получает класс «изменено» по опкоду difflib без признака семантического анализа

#### Scenario: Сетевая ошибка без повторной попытки
- **Дано** соединение с LLM-сервером невозможно
- **Когда** выполняется семантическая классификация фрагмента с операцией `replace`
- **То** отправлен ровно один запрос к LLM, без повторной попытки
- **И** фрагмент получает класс «изменено» по опкоду difflib без признака семантического анализа
