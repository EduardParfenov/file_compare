## ADDED Requirements

### Requirement: Сравнение пары одного формата
Система SHALL принимать к сравнению только пару файлов с одинаковым
расширением. `POST /api/compare` MUST отклонять запрос с кодом 400 и JSON
с полем `error`, если расширения двух загруженных файлов различаются, и
MUST NOT создавать задачу сравнения в этом случае. Проверка MUST
выполняться до конвертации и до первого обращения к модели. Веб-страница
MUST NOT допускать запуск сравнения для пары с разными расширениями и MUST
показывать причину, по которой запуск недоступен.

#### Scenario: Смешанная пара отклоняется
- **Дано** загружены файлы `contract_v1.docx` и `contract_v2.pdf`
- **Когда** клиент отправляет `POST /api/compare` с их идентификаторами
- **То** ответ имеет код 400 и JSON с полем `error`
- **И** задача сравнения не создана

#### Scenario: Пара одного формата принимается
- **Дано** загружены файлы `contract_v1.pdf` и `contract_v2.pdf`
- **Когда** клиент отправляет `POST /api/compare` с их идентификаторами
- **То** ответ имеет код 202 и содержит `job_id`

#### Scenario: Проверка выполняется до обращения к модели
- **Дано** загружены файлы разных расширений, одно из которых —
  сканированный PDF
- **Когда** клиент отправляет `POST /api/compare`
- **То** ответ имеет код 400
- **И** модель для чтения страниц не вызывалась

#### Scenario: Кнопка запуска недоступна при разных расширениях
- **Дано** в первой зоне загружен `.docx`, во второй — `.pdf`
- **Когда** пользователь смотрит на кнопку «Начать сравнение»
- **То** кнопка неактивна
- **И** отображается причина, по которой сравнение недоступно

#### Scenario: Одинаковое расширение независимо от регистра
- **Дано** загружены файлы `report_v1.DOCX` и `report_v2.docx`
- **Когда** клиент отправляет `POST /api/compare` с их идентификаторами
- **То** ответ имеет код 202 и содержит `job_id`

## MODIFIED Requirements

### Requirement: Парная конвертация PDF
Пайплайн сравнения двух PDF-файлов SHALL выполнять конвертацию парной
функцией, принимающей оба пути: выбор страниц для чтения, выравнивание
страниц и кропы требуют обоих документов. Сравнение пары файлов одного
формата, отличного от PDF, SHALL выполняться пофайловой конвертацией без
изменений; пары файлов с разными расширениями до конвертации не доходят
(см. требование «Сравнение пары одного формата»). Результат парной
конвертации MUST включать блоки обеих сторон, выравнивание страниц, кропы
и признак усечения кропов.

#### Scenario: Два PDF конвертируются совместно
- **Дано** сравниваются два сканированных PDF
- **Когда** выполняется конвертация
- **То** конвертация выполнена одной функцией, получившей оба пути
- **И** результат содержит блоки обеих сторон и выравнивание страниц

#### Scenario: Сравнение .docx не меняется
- **Дано** сравниваются два файла `.docx`
- **Когда** выполняется конвертация
- **То** каждая сторона конвертируется пофайловой функцией
- **И** модель для чтения страниц не используется

#### Scenario: Признак усечения кропов в результате
- **Дано** кропы превысили настроенный лимит
- **Когда** формируется результат задачи
- **То** результат содержит признак усечения кропов
