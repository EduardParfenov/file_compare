## Why

В настоящее время загрузка файла валидируется только по расширению имени
(`app/services/uploads.py:30`). Пользователь может перебить расширение
произвольного файла (например, `.png` → `.docx`) и обойти проверку
`ALLOWED_EXTENSIONS`. Таковой файл сохранится в `UPLOAD_DIR`, получит
`upload_id` и пойдёт в конвертер, что может привести к некорректным
ошибкам, потере данных или потенциальной уязвимости при парсинге чужого
формата. Нужно дополнительно проверять магические байты (сигнатуру файла)
для поддерживаемых форматов.

## What Changes

- Добавить проверку магических байт загружаемого файла в
  `app/services/uploads.py` (`save_upload`) до сохранения на диск:
  для `.pdf` — сигнатура `%PDF`, для `.docx` — сигнатура ZIP `PK\x03\x04`.
- Если сигнатура не совпадает с заявленным расширением — отклонить файл
  с кодом 400 и JSON `{"error": "Содержимое файла не соответствует расширению <ext>"}`,
  не сохранять в `UPLOAD_DIR`. `<ext>` — расширение из имени файла (например, `.docx`).
- Покрыть тестами: валидный файл с верным расширением принимается; файл с
  подложным расширением (правильные байты, неправильное расширение) и файл
  с правильным расширением, но чужим содержимым — отклоняются с кодом 400 и
  сообщением `{"error": "Содержимое файла не соответствует расширению <ext>"}`.

## Capabilities

### New Capabilities

Нет — новые возможности не вводятся.

### Modified Capabilities

- `file-upload`: валидация загружаемого файла дополняется проверкой
  магических байт (содержимого файла), а не только расширения имени.
  Требование «Отклонение неподдерживаемого формата» расширяется:
  файл с подходящим расширением, но неподходящим содержимым, тоже
  отклоняется кодом 400.

## Impact

Код: `app/services/uploads.py` (функция `save_upload`).
Тесты: `tests/test_upload.py` (новые сценарии magic bytes).
API: без изменений (код 400 уже существует для неподдерживаемого формата).
Зависимости: без изменений.

Уровень: исправление
