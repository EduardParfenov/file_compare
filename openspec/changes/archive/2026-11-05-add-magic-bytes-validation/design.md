## Context

Текущая реализация валидации загрузки в `app/services/uploads.py` (`save_upload`)
проверяет только расширение имени файла (`os.path.splitext(original_name)[1].lower()`)
среди `ALLOWED_EXTENSIONS`. Содержимое файла не проверяется: файл с любым
содержимым и правильным расширением сохраняется в `UPLOAD_DIR`. См. proposal.md
— Why для мотивации.

## Goals / Non-Goals

**Goals:**

- Добавить проверку сигнатуры файла (магических байт) в `save_upload` до
  сохранения на диск: `.pdf` → `%PDF`, `.docx` → `PK\x03\x04` (ZIP).
- Отклонять файл кодом 400, если сигнатура не совпадает с расширением,
  не сохраняя его в `UPLOAD_DIR`.
- Сохранить существующее поведение для файлов с верным расширением и
  верным содержимым.

**Non-Goals:**

- Антивирусное сканирование или глубокий анализ содержимого документа.
- Проверка внутренней структуры docx/pdf (валидность ZIP, парсинг PDF).
- Поддержка дополнительных форматов Beyond `.docx` и `.pdf`.

## Decisions

1. **Где проверять:** в `app/services/uploads.py` (`save_upload`), сразу после
   определения расширения и перед `file_storage.save(path)`. Файловый объект
   перемотать обратно (`seek(0)`) после чтения сигнатуры, чтобы сохранение
   шло с начала.

2. **Сигнатуры:** `.docx` — `PK\x03\x04` (ZIP-архив, DOCX — это ZIP), `.pdf`
   — `%PDF`. Проверка ограничивается первыми 4 байтами файла.

3. **Сообщение об ошибке:** код 400 с JSON `{"error": "Содержимое файла не соответствует расширению <ext>"}`,
   где `<ext>` — расширение из имени файла (например, `.docx` или `.pdf`).
   Сообщение указывает на несоответствие содержимого и расширения, без
   раскрытия внутренних деталей (сигнатур, путей к файлам).

4. **Тесты:** добавить сценарии в `tests/test_upload.py` — валидный файл
   принимается, файл с подложным расширением отклоняется, файл с правильным
   расширением но чужим содержимым отклоняется.

## Risks / Trade-offs

- [Подделка сигнатуры] Злоумышленник может prefixes файл нужными магическими
  байтами; проверка защищает от простой смены расширения, но не от целенаправленной
  подделки. Это приемлемый риск для текущей угрозы.
- [DOCX = ZIP] Любой ZIP-файл пройдёт сигнатуру `.docx`; более глубокая
  валидация структуры DOCX вынесена за область этого change'а.
- [seek на потоке] Не все файловые объекты поддерживают `seek(0)`;
  Werkzeug `FileStorage` поддерживает, что достаточно для Flask.
