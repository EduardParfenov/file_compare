# Design: redesign-page-layout-wide

## Context

См. proposal.md — Why. Текущее состояние: `body` в `style.css` ограничен
`max-width: 1200px` с `margin: 0 auto`; шапка (`h1` + `p`) — обычные
блочные элементы без обёртки, выровнены по левому краю. Фронтенд —
vanilla CSS без фреймворков, адаптивность решается чисто средствами CSS.

## Goals / Non-Goals

**Goals:**
- Страница использует 90% ширины окна (до 1920px), адаптируясь при
  изменении размера окна без JS.
- Шапка (заголовок + подпись) визуально центрирована.
- Контролы (зоны загрузки, кнопка, степпер, уведомления) — компактной
  ширины и по центру; широкой остаётся только область diff-результата.

**Non-Goals:**
- Редизайн палитры, кнопок, степпера и панелей diff — не входит в scope.
- Поддержка узких экранов (перестройка панелей вертикально, медиазапросы)
  — не входит в scope.
- Изменения логики `app.js` — не требуются.

## Decisions

### D1: Резиновая ширина 90% с потолком 1920px

`body { width: 90%; max-width: 1920px; margin: 0 auto; padding: 24px; }`
вместо текущих 1200px. Процентная ширина даёт пропорциональную адаптацию
к окну браузера (включая окна уже 1200px), потолок защищает от слишком
длинных строк на ультрашироких мониторах (>2134px viewport), а
`margin: auto` сохраняет центрирование. Медиазапросы и JS не нужны.

Альтернативы:
- Полностью резиновая без потолка — на 2560px+ строки текста становятся
  нечитаемо длинными.
- Только `max-width: 1920px` без процентной ширины — на окнах 1200-1920px
  страница не использует пропорциональные поля, прижата к краям окна
  вплоть до padding.

### D2: Обёртка шапки в `<header class="page-header">`

`h1` и `p` оборачиваются в семантический `<header>` со стилем
`text-align: center`. Стили применяются к классу, а не к тегам
`h1`/`p` напрямую, чтобы не затронуть заголовки `h2` панелей и возможные
другие параграфы. Точка в конце подписи убирается в разметке.

Альтернатива: `text-align: center` прямо на `h1, p` — хрупко, ломается
при добавлении новых параграфов на страницу.

### D3: Двухъярусная раскладка — центрированная колонка контролов

Паттерн diff-страниц GitHub/GitLab: контролы — в узкой центрированной
колонке, результат — на всю ширину. Зоны загрузки, кнопка «Начать
сравнение», степпер и уведомления (error/degraded) оборачиваются в
`<div class="controls">` со стилем
`.controls { max-width: 1150px; margin: 0 auto; }` — это восстанавливает
прежние пропорции зон загрузки (~568px каждая, как при ширине страницы
1200px) и даёт единую центральную ось: шапка → зоны → кнопка → степпер.
Кнопка сравнения центрируется (`.actions { text-align: center }`),
степпер — через `justify-content: center`. Панели diff остаются вне
колонки и занимают всю ширину страницы.

Альтернативы:
- Центрировать только зоны загрузки — кнопка и степпер остались бы слева,
  ломая центральную визуальную ось страницы.
- Оставить зоны на всю ширину — кнопки «Открыть файл» визуально
  «разъезжаются», зоны выглядят растянутыми.

## Risks / Trade-offs

- [Широкие таблицы всё равно могут не влезть в панель при очень большом
  числе колонок] → Существующий `overflow-x: auto` на `.diff-table`
  остаётся как запасной механизм прокрутки.
- [Пользователи с окном уже 1200px не заметят изменений ширины] →
  Приемлемо: поведение на узких окнах сохраняется прежним.
