уровень: исправление

## Why

Сравнение двух **различающихся** PDF завершается сообщением «Документы совпадают
по тексту и по изображению» и не показывает ни одного различия, хотя пайплайн их
посчитал. Проверено на реальной паре PDF из `uploads/`: сервер отдал 6
фрагментов и 15 строк результата, а интерфейс показал сообщение о совпадении и
выбросил все 15 строк.

Причина — инвертированное условие в клиенте (`app/static/app.js:570`): сообщение
о совпадении показывается тогда, когда список неизменённых страниц **пуст**,
т.е. ровно когда документы различаются. Для действительно одинаковых PDF
сообщение, наоборот, не появляется: вместо него выводится свёрнутый диапазон
«страницы 1–3 без изменений» вместе с полным содержимым тех же страниц. Оба
поведения противоречат требованиям `diff-viewer` («Свёртывание неизменённых
страниц», сценарий «Документы полностью совпадают») и `pdf-conversion`
(«Показ страниц в результате сравнения»).

Сравнение `.docx` не затронуто: у результата нет поля `pages`, поэтому условие
не выполняется. Проверено в браузере — поведение прежнее.

Дефект не пойман тестами: клиент не покрыт тестами вообще (`REVIEW.md`, §1), а
серверные проверки свёрнутых диапазонов проходят, поскольку неверно именно
решение «показывать сообщение или строки», а не сами строки.

## What Changes

- Признак «документы полностью совпадают» вычисляется на сервере и передаётся в
  результате задачи отдельным полем. Клиент рисует сообщение по этому признаку и
  больше не решает задачу полного совпадения самостоятельно.
- Условие показа сообщения становится таким, как его описывают спеки: различий
  нет ни по тексту, ни по изображению, страницы не деградировали. Различие,
  найденное только по изображению (текст совпал, картинка заменена), совпадением
  больше не считается.
- Для полностью совпадающих PDF показывается сообщение о совпадении, а
  свёрнутые диапазоны страниц не выводятся, как требует сценарий «Документы
  полностью совпадают».
- Страница, признанная визуально неизменной, больше не показывается дважды.
  Сейчас в ветке текстового слоя она даёт и своё содержимое (текст достаётся
  бесплатно, все страницы конвертируются), и свёрнутую строку диапазона. Блоки
  неизменённых страниц исключаются из сравнения — так же, как ветка чтения
  моделью не читает их вовсе, — и страница показывается только свёрнутой.
- Сравнение `.docx` не меняется: у результата нет поля `pages`, признак
  полного совпадения не вычисляется, поведение прежнее.

Вне области действия: сравнение `.docx`; порог `IDENTITY_IOU_THRESHOLD`
(`page-image-diff`) и его консервативность — из-за него реально почти
неизменные страницы не попадают в `unchanged` и свёртывание на практике
редко применяется, но это отдельная задача со своими измерениями; настройка
`PDF_CROPS_MAX_BYTES`, которая не доходит до конвертации; неиспользуемая
`OCR_CONCURRENCY`; нулевая температура в запросе чтения страниц, требуемая
`vision-ocr`.

## Capabilities

### New Capabilities

- Нет: все требования, которых косается исправление, уже сформулированы;
  добавляется лишь поле результата, выражающее существующее требование о
  сообщении при полном совпадении.

### Modified Capabilities

- `diff-viewer`: «Свёртывание неизменённых страниц» — сообщение о полном
  совпадении показывается по признаку из результата задачи, а не по отсутствию
  неизменённых страниц; для совпадающих документов свёрнутые диапазоны не
  выводятся.
- `comparison-jobs`: новое требование «Признак полного совпадения документов» —
  сервер вычисляет признак по различиям текста и изображений и по состоянию
  страниц, отдаёт его в результате задачи.
- `pdf-conversion`: «Показ страниц в результате сравнения» — страница,
  признанная неизменной, показывается только свёрнутым диапазоном; её
  содержимое в ветке текстового слоя не выводится повторно.

## Impact

- **Код**: `app/services/jobs.py` (признак полного совпадения, исключение
  блоков неизменённых страниц перед diff), `app/services/conversion.py`
  (ненулевые `read_old`/`read_new` для ветки текстового слоя),
  `app/static/app.js` (рисование сообщения по признаку, без раннего `return`).
- **API**: результат `GET /api/jobs/<job_id>` для сравнения PDF дополняется
  булевым полем `identical`. Для `.docx` поле не появляется.
- **Тесты**: серверные проверки признака во всех сочетаниях (различия по
  тексту, различия только по изображению, деградация страниц, полное
  совпадение) и проверка отсутствия дубля неизменённой страницы; фикстуры
  `tests/pdf_fixtures.py` достаточны, сеть не используется, модель мокается.
- **Зависимости и конфигурация**: не меняются.
- **Документы**: `REVIEW.md` — пункт о непокрытом клиенте дополняется указанием,
  что решение о сообщении о совпадении перенесено на сервер и покрыто тестами.
- **Версия**: при архивации — patch, `VERSION` 2.0.0 → 2.0.1.
