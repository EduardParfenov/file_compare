## ADDED Requirements

### Requirement: Блокирующий статус проверок
Прогон конвейера на pull request SHALL быть блокирующим для слияния: PR в
`master` вливается только при успешном прохождении всех шагов на текущем
head PR. Способ обхода проверок (force-merge, слияние при красном прогоне,
отключение отдельных шагов ради выпуска) MUST NOT применяться. Перед
отправкой коммитов в remote SHALL выполняться локальный прогон тех же
команд с версиями инструментов из `requirements-dev.txt`
(`ruff format --check .`, `ruff check .`, `pytest`,
`openspec validate --all --strict`): локальный красный результат означает
красный прогон на раннере, поскольку конвейер не содержит собственных
настроек линтера и форматтера.

#### Scenario: Прогон на pull request зелёный
- **WHEN** все шаги конвейера на текущем head PR завершились успешно
- **THEN** статус PR допускает слияние в `master`

#### Scenario: Шаг конвейера упал
- **WHEN** шаг конвейера на текущем head PR завершился ошибкой
- **THEN** PR не сливается до устранения причины в ветке PR и повторного
  успешного прогона

#### Scenario: Локальная проверка красная
- **WHEN** локальный прогон `ruff format --check .` или `ruff check .`
  завершился ошибкой
- **THEN** коммиты не отправляются в remote до исправления, поскольку тот же
  прогон на раннере завершится ошибкой
