## MODIFIED Requirements

### Requirement: Журналирование проглоченных сбоев
Каждый сбой, который приложение намеренно проглатывает и продолжает работу, MUST быть записан в журнал. При чтении страниц запись MUST содержать номер страницы и причину сбоя (тип исключения), но не адрес сервиса и не ключ API. Сбой чтения страницы при раскрытии свёрнутого диапазона (`read_page_range`) MUST фиксироваться в журнале с номером страницы.

#### Scenario: Модель недоступна при чтении страниц
- **Дано** модель чтения страниц недоступна
- **Когда** страница не прочитана и разметка помечена как непрочитанная
- **То** причина недоступности записана в журнал
- **И** номер страницы указан в записи

#### Scenario: Классификатор недоступен
- **Дано** chat-модель классификатора вернула ошибку
- **Когда** приложение переходит к алгоритмическим меткам
- **То** причина сбоя записана в журнал

#### Scenario: Сбой без последствий для результата
- **Дано** повреждённая страница не помешала определить наличие текстового слоя
- **Когда** страница пропущена и проверка продолжается
- **То** пропуск зафиксирован в журнале

#### Scenario: Сбой раскрытия диапазона зафиксирован с номером страницы
- **Дано** при раскрытии свёрнутого диапазона страница не прочитана
- **Когда** пишется запись журнала о сбое
- **То** в записи указан номер страницы и причина сбоя
- **И** адрес сервиса и ключ API в записи отсутствуют
