# Proposal: add-project-version

уровень: исправление

## Why

Правила проекта (AGENTS.md) требуют повышать версию при архивации каждого
change'а (major/patch по уровню proposal), но самой версии в проекте нет:
ни `VERSION`, ни `pyproject.toml`, ни `__version__` — правило неприменимо.
Кроме того, версия приложения нигде не видна пользователю.

## What Changes

- Добавить файл `VERSION` в корень репозитория с начальной версией `0.1.0`
  (semver).
- Приложение при старте читает `VERSION` и кладёт версию в конфиг
  (`APP_VERSION`); файл закоммичен, поэтому при его отсутствии используется
  запасное значение без падения приложения.
- Показывать версию в UI: подвал главной страницы (`index.html`).
- Зафиксировать правило версионирования: при архивации change'а `VERSION`
  повышается по уровню proposal («несовместимое поведение» → major,
  «исправление» → patch); minor не используется.
- Тесты: версия читается из `VERSION` в конфиг; версия присутствует в HTML
  главной страницы.

## Capabilities

### New Capabilities

- `project-version`: хранение версии проекта в файле `VERSION` (semver),
  чтение версии приложением при старте, отображение версии в UI, правило
  повышения версии при архивации change'ов.

### Modified Capabilities

(пусто — требования существующих возможностей не меняются)

## Impact

- Новые файлы: `VERSION`, спека `project-version`.
- Изменённые файлы: `app/__init__.py` (чтение VERSION в конфиг),
  `app/routes.py` и/или `app/templates/index.html` (отображение),
  возможно `app/static/style.css` (стили подвала), тесты, `AGENTS.md`
  (структура проекта — файл VERSION).
- Поведение существующих эндпоинтов и форматов API не меняется.
