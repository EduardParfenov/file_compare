## Purpose

Единый источник версии проекта (файл VERSION в корне, semver), читаемый
приложением и видимый пользователю в UI, с правилом повышения версии при
архивации change'ов.

## ADDED Requirements

### Requirement: Файл VERSION как источник версии
Версия проекта SHALL храниться в файле `VERSION` в корне репозитория в
формате semver (`MAJOR.MINOR.PATCH`). Файл `VERSION` SHALL быть
закоммичен в репозиторий.

#### Scenario: Файл существует и валиден
- **WHEN** открыт файл `VERSION` в корне репозитория
- **THEN** он содержит одну строку вида `MAJOR.MINOR.PATCH` (например, `0.1.0`)

### Requirement: Чтение версии приложением
Приложение SHALL при старте читать версию из файла `VERSION` и помещать её
в конфигурацию. При отсутствии или нечитаемости файла приложение MUST NOT
падать: используется запасное значение.

#### Scenario: Успешное чтение
- **WHEN** приложение стартует и файл `VERSION` содержит `0.1.0`
- **THEN** конфиг приложения содержит версию `0.1.0`

#### Scenario: Файл отсутствует
- **WHEN** приложение стартует без файла `VERSION`
- **THEN** приложение работает, а версия принимает запасное значение

### Requirement: Отображение версии в UI
Главная страница SHALL отображать текущую версию приложения в подвале.

#### Scenario: Версия на странице
- **WHEN** пользователь открывает главную страницу
- **THEN** в подвале страницы отображается версия, совпадающая с содержимым
  файла `VERSION`

### Requirement: Повышение версии при архивации
При архивации change'а версия в `VERSION` SHALL повышаться по уровню его
proposal: «несовместимое поведение» — major, «исправление» — patch.
Компонент minor MUST NOT использоваться.

#### Scenario: Архивация change'а уровня «исправление»
- **WHEN** change уровня «исправление» архивируется при версии `0.1.0`
- **THEN** версия в `VERSION` становится `0.1.1`

#### Scenario: Архивация change'а уровня «несовместимое поведение»
- **WHEN** change уровня «несовместимое поведение» архивируется при версии `0.1.1`
- **THEN** версия в `VERSION` становится `1.0.0`
