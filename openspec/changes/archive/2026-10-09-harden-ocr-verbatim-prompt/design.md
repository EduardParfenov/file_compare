# Design: harden-ocr-verbatim-prompt

## Context

Роль чтения страниц реализована в `app/services/vision_ocr.py`: страница уходит одним мультимодальным запросом с `SystemMessage(SYSTEM_PROMPT)` и `HumanMessage` с изображением. Текущая инструкция — мягкая («Ты — OCR… Верни её содержимое в markdown… Не додумывай отсутствующий текст»): она не запрещает пересказ и сокращения, и реальная модель (`qwen3-vl-8b`) ими пользуется (REVIEW.md, «Качество чтения настоящей модели на сложных сканах»). Кэш страниц (`cache_key`) включает `PROMPT_VERSION`, поэтому любое изменение текста инструкции требует повышения дефолтной версии, иначе старые (пересказанные) ответы продолжат попадаться из кэша. Дефолт `OCR_PROMPT_VERSION` дублируется в `app/__init__.py` (env-переменная, fallback `"v1"`), `.env.example` и README — их надо менять синхронно с `PROMPT_VERSION`.

## Goals / Non-Goals

**Goals:**
- Системная инструкция явно требует дословного переноса и запрещает суммирование/пересказ/сокращения/paraphrasing.
- Кэш страниц перечитывается после изменения инструкции (повышение дефолтной версии до `v2`).
- Обязательные элементы новой инструкции зафиксированы тестами на уровне содержимого `SYSTEM_PROMPT`.

**Non-Goals:**
- Гарантия дословности со стороны модели: промпт снижает, но не устраняет риск пересказа (модель — недетерминированный компонент; README-ограничение сохраняется в смягчённой формулировке).
- Менять параметры вызова (temperature, таймауты), конфигурацию модели или формат markdown-вывода.
- Реализовывать автоматическую детекцию пересказа/сокращения в ответе модели.
- Пересчитывать кэш на диске — кэш процессный (`_CACHE` в памяти), повышение версии достаточно.

## Decisions

1. **Ужесточение `SYSTEM_PROMPT` на русском языке, без смены языка инструкции.** Модель работает со смешанными документами (ru/en); русскоязычная инструкция уже показала работоспособность на `real_model_check`. Альтернатива (перевод инструкции на английский как более «типичный» для VL-моделей) — отклонена: нет данных о выигрыше, а смена языка усложняет сверку с REVIEW/тестами на русском.

2. **Содержание новой инструкции: дословность + явные запреты + полнота переноса.** Формулировки: «дословно, word-for-word», запрет «summarize / paraphrase / shorten / skip», требование переносить все видимые фрагменты (колонтитулы, сноски, мелкий шрифт), запрет добавлений от модели. Альтернатива (оставить мягкий промпт и полагаться на few-shot примеры) — отклонена: увеличивает размер запроса и стоимость, противоречит решению «один запрос — одна страница» без примеров.

3. **Повышение `PROMPT_VERSION` до `"v2"` одновременно с правкой текста.** Версия — часть ключа кэша и «идентификатор текста инструкции»; оставить `v1` при новом тексте — значит отдавать старые пересказанные ответы. Правятся: `PROMPT_VERSION` в `vision_ocr.py`, fallback в `app/__init__.py`, комментарий в `.env.example`, таблица в README. Пользовательский `OCR_PROMPT_VERSION` из env продолжает иметь приоритет — операционное правило без изменений.

4. **Тесты — проверка содержимого `SYSTEM_PROMPT`, а не «поведения модели».** pytest ходит в сеть запрещено; фиксируем контракт инструкции: наличие требований дословности и запрета сокращений в тексте, `PROMPT_VERSION == "v2"`, дефолт приложения `"v2"`. Альтернатива (снять скрытый маркер из ответа мока) — бессмысленна: мок не «решает» по промпту.

5. **Ограничение README сохраняется, формулировка уточняется.** После ужесточения риск пересказа остаётся (модель не гарантирует дословность), поэтому limitation не удаляется, а уточняется: инструкция требует дословности, но модель может отклоняться; REVIEW.md — отложенная задача помечается закрытой этим change.

## Risks / Trade-offs

- [Жёсткая инструкция не гарантирует дословности на всех моделях/сканах] → смягчённая формулировка README-ограничения; визуальный кроп остаётся источником истины для глаз; при появлении реальных провалов — отдельный change (детекция или смена модели).
- [Повышение версии инвалидирует кэш — повторные сравнения перечитывают страницы (время/стоимость)] → одноразовая плата за корректный текст; кэш процессный, дисковой миграции нет.
- [Более длинная инструкция чуть увеличивает input-токены каждого запроса чтения] → инструкция на уровне абзаца, доля от изображения мала; отказ от few-shot keeps запрос компактным.

## Migration Plan

Деплой — обычный: изменение текста константы и дефолтов. Откат — revert коммита; кэш со старой версией в новом коде не ищется (ключ другой), откат вернёт `v1` и старый кэш в памяти процесса исчезнет при рестарте — безопасно. Миграция данных отсутствует.
