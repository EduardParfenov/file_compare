## MODIFIED Requirements

### Requirement: In-memory хранилища задач и загрузок
Реестры загруженных файлов и задач сравнения SHALL храниться в памяти
процесса: данные MUST NOT переживать перезапуск приложения. После
перезапуска запрос с `upload_id` из прошлой сессии MUST отклоняться с
кодом 404 как запрос с неизвестным идентификатором. Доступ к реестрам MUST
быть потокобезопасным: конкурентные HTTP-запросы (загрузка файлов, создание
и опрос задач) MUST не терять записи реестров и MUST не приводить к
некорректному состоянию реестров.

#### Scenario: Идентификатор из прошлой сессии
- **Дано** файл был загружен до перезапуска приложения
- **Когда** клиент отправляет `POST /api/compare` с `upload_id` из прошлой сессии
- **То** ответ имеет код 404 и JSON с полем `error`

#### Scenario: Конкурентные загрузки и запуски задач
- **Дано** несколько клиентов одновременно отправляют запросы `POST /api/upload` и `POST /api/compare` одному процессу приложения
- **Когда** запросы выполняются конкурентно
- **То** каждая запись реестра доступна по своему идентификатору после создания
- **И** ни одна запись не теряется из-за гонки доступа к реестру
