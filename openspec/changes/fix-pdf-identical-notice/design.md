## Context

Текущее состояние, важное для решения (мотивация — в `proposal.md`).

Результат задачи — единый словарь: `rows[]` (строки side-by-side), `semantic`,
`fragments_count`, а для PDF дополнительно `pages` (сводка выравнивания),
`crops`, `crops_truncated`. `GET /api/jobs/<job_id>` отдаёт его как есть.

`_build_rows` (`app/services/jobs.py:443`) собирает строки из фрагментов, но
`emit_equal` в конце (строка 524) выводит **все** оставшиеся блоки обеих
сторон, включая совпадающие: строки результата — это весь документ, а не только
изменённые места. Поэтому «строк много» не означает «различий много», и
признак совпадения по числу строк вывести нельзя.

Различия по изображению не видны в `find_diffs`: он сравнивает только текст
(`diffing.py:92`). Заметка о замене картинки при совпавшем тексте рождается
позже — либо флагом `images_changed` на парной строке (`jobs.py:379`), либо
односторонними под-строками изображений, выровненных по sha1
(`_image_subrows`, `jobs.py:397`). Оба сигнала существуют только в строках
результата.

Признак «все страницы неизменны» сервер выдаёт как `pages.unchanged`
(`_page_summary`, `jobs.py:314`). Он не эквивалентен совпадению документов: у
двух различающихся PDF он пуст, а у двух совпадающих — заполнен. Именно его
инвертированное использование в клиенте и породило дефект
(`app/static/app.js:570`).

`_group_by_page` (`jobs.py:217`) вставляет свёрнутые диапазоны по
`conversion["unchanged"]` и строки непрочитанных страниц; при полном совпадении
(строк нет) возвращает только маркеры (`jobs.py:239-240`) с расчётом на то, что
клиент покажет отдельное сообщение.

Две ветки конвертации PDF расходятся в одном месте: ветка чтения моделью
получает список страниц к чтению из `align_pages` и **не создаёт блоки**
неизменённых страниц (`conversion.py:105-116`), а ветка текстового слоя
конвертирует **все** страницы и возвращает `read_old`/`read_new` как множества
страниц присутствующих блоков (`conversion.py:247-248`). Отсюда дубль: у
неизменённой страницы есть и блоки, и маркер свёрнутого диапазона.

Поля `read_old`/`read_new` ветки текстового слоя нигде в пайплайне не читаются
(единственные потребители — конструкторы словарей в `conversion.py` и `jobs.py`),
поэтому семантику «страницы, чьё содержимое участвует в сравнении» можно
выровнять без поиска потребителей.

Клиент не покрыт тестами (`REVIEW.md`, §1): решение «показать сообщение или
строки» принимается в браузере и потому не защищено ничем.

## Goals / Non-Goals

**Goals:**

- Одно место, где принимается решение о полном совпадении документов, и это
  место покрыто тестами `pytest`.
- Условие показа сообщения выражает смысл требований, а не состав страниц.
- Страница не выводится дважды: неизменённая — только свёрнутым диапазоном.
- Сравнение `.docx` не меняется ни в одном наблюдаемом аспекте.

**Non-Goals:**

- Изменение порогов `page-image-diff` и качества распознавания страниц.
- Перенос логики отображения из браузера на сервер; сервер отдаёт признак,
  клиент по-прежнему решает, что рисовать.
- Тесты клиента (сборщик в проекте отсутствует).

## Decisions

### D1. Признак совпадения считает сервер и отдаёт полем результата

`run_pipeline` добавляет в результат булево поле `identical` только для
сравнения PDF. Клиент рисует сообщение по этому полю и ничего не вычисляет
сам.

Почему сервер: он единственный, кто видит фрагменты, различие изображений и
состояние страниц; он же покрыт тестами. Клиент получает крупный JSON и
`rows[]`, в котором различия текста и под-строки изображений смешаны с
уравнивающими блоками, — вывод признака там означал бы дублирование
серверной семантики в непокрытом тестами месте.

Альтернатива A — оставить решение в `app.js`, исправив условие на
`fragments_count === 0 && !degraded_pages.length`. Отклонена по двум причинам:
клиент не покрыт тестами (дефект и не пойман именно поэтому), а условие не
видит различия только по изображению — они появляются в строках, а не во
фрагментах.

Альтернатива B — считать совпадением «`pages.unchanged` покрывает все
страницы». Отклонена: это и есть исходный баг в зеркальном виде, и условие
ложно для пар, у которых текст совпадает, а картинка на странице заменена.

Совместимость: поле аддитивное, для `.docx` отсутствует; клиент, который его
не знает, продолжает работать как раньше.

### D2. Совпадение — это отсутствие различий по тексту, по изображению и по состоянию страниц

Признак истинен, когда одновременно: фрагментов нет; выравнивание страниц не
нашло различий (нет изменённых пар страниц и страниц, присутствующих только в
одном файле); ни одна строка не несёт `images_changed` и ни одна односторонняя
строка не несёт изображений; нет непрочитанных и деградировавших страниц.

Почему проверять страницы по выравниванию: различие текста страницы читатель
может и не увидеть — сканы читаются неидеально, а ветка текстового слоя
страницы, признанные неизменными, вообще не сравнивает. Но различие картинок
страницы уже измерено попиксельно, и объявить документы совпадающими при таком
измерении означало бы повторить исходный дефект в новом месте: совпавших
страниц у различающихся документов как раз нет.

Почему проверять изображение по строкам: `find_diffs` работает по тексту, и
замена встроенной картинки при совпавшем тексте порождает либо
`images_changed` на парной строке, либо односторонние под-строки изображений.
Это различие может не попасть в выравнивание страниц (картинка может не
участвовать в рендере), поэтому проверка страницы не заменяет проверку строк.

Почему учитывать состояние страниц: непрочитанная или деградировавшая
страница — это неизвестность, а не совпадение; выдавать за неё сообщение о
совпадении нельзя (та же логика уже применена к баннеру деградированного
режима).

Признак считается по строкам до `_group_by_page`: маркеры диапазонов и
непрочитанных страниц не несут информации о различиях и в подсчёте не
участвуют.

Условие по страницам добавлено при реализации: перечень в первоначальной
редакции этого решения перечислял только признаки строк, что противоречило
требованию «нет различий по изображению».

### D3. Блоки неизменённых страниц исключаются до сравнения, а не после

В ветке текстового слоя блоки страниц, признанных неизменными, отбрасываются
по номерам из `alignment.identical` (у каждой стороны свой номер страницы) до
`find_diffs`.

Почему до, а не после: `_build_rows` получает полные последовательности блоков
и сам выводит уравнивающие участки (`emit_equal`), поэтому отфильтровать
страницы на уровне строк нельзя — они уже в строках; фильтрация после
сборки строк ломала бы соответствие между блоками и фрагментами, из которых
строки собраны.

Побочный эффект в пользу подхода: уменьшается объём диффа, а каскадные
фрагменты не могут протянуться через неизменённые страницы.

Альтернатива — оставить блоки и убрать маркер свёрнутого диапазона для
страниц, уже присутствующих в строках. Отклонена: страница тогда показывается
содержимым вместо свёртки, а требование «диапазон страниц, не содержащий
изменений, MUST отображаться свёрнутым» перестаёт выполняться — свёртка в
ветке текстового слоя не работала бы никогда.

Симметрия с веткой чтения моделью — тоже аргумент: там неизменённая страница
не читается и в сравнении не участвует по построению. После изменения обе
ветки ведут себя одинаково.

Номера страниц при этом не перенумеровываются: `page` в блоке остаётся
исходным, поэтому подписи страниц и свёрнутые диапазоны показывают
нумерацию своих документов.

### D4. `read_old`/`read_new` ветки текстового слоя считаются по оставшимся блокам

После фильтрации множества страниц, чьё содержимое участвует в сравнении,
вычисляются по оставшимся блокам — тем же способом, что и в ветке чтения
моделью. Поле остаётся непрочитанным потребителями, но перестаёт вводить в
заблуждение того, кто его прочитает.

### D5. Клиент теряет условие по составу страниц целиком

Блок в `renderResult`, вычислявший признак по `result.pages.unchanged` и
`degraded_pages`, заменяется проверкой `result.identical`. Ранний выход
остаётся, но теперь он достижим только при признаке совпадения, который
сервер выставил осознанно.

Побочно устраняется вторая половина дефекта: для полностью совпадающих PDF
сообщение появляется, а маркеры свёрнутых диапазонов не рисуются, как требует
сценарий «Документы полностью совпадают».

Случай `.docx` не меняется: поля `identical` у него нет, условие ложно, строки
рисуются как раньше.

### D6. Проверки живут в `tests/test_pdf_pipeline.py`

Сценарии признака и отсутствия дубля страницы — продолжение существующих
проверок `TestPageSummary`/`TestCollapsedRanges`, им нужны те же фикстуры
`tests/pdf_fixtures.py` и тот же мок модели. Отдельный файл не нужен.

Сценарий различия только по изображению строится на паре текстовых PDF с
одинаковым текстом и разными картинками — фикстуры пишут текстовый слой,
для картинок используется существующий путь встроенных изображений
(`pdf_converter._embedded_images`).

## Risks / Trade-offs

- [Правка в текстовом слое страницы, визуально совпавшей с другой, будет
  скрыта в свёрнутом диапазоне] → Риск унаследован: ветка чтения моделью
  ведёт себя так же по построению, а требование «показывать все блоки
  страниц, подлежавших чтению» сформулировано именно так. Смягчение —
  раскрытие диапазона добывает текст страницы с сервера, поэтому правка
  остаётся достижимой; свёртка применяется только к страницам с IoU выше
  консервативного порога.
- [Сообщение «совпадают по тексту и по изображению» при исключённых из
  сравнения страницах] → Формулировка принята в проекте ранее и относится к
  сканам, где текст неизменённых страниц тоже не читается; текст сообщения не
  меняется, чтобы не расходиться с уже опубликованным интерфейсом.
- [Фильтрация блоков меняет длины последовательностей для `SequenceMatcher`] →
  Уменьшение объёма не меняет качество выравнивания, а номера страниц в
  строках остаются исходными; регрессия ловится тестом на смешанной паре
  (одна страница совпала, другая отличается).
- [Признак верен при `fragments_count == 0`, но страница не прочитана] →
  Учитывается `degraded_pages` и `unreadable`; при недоступности модели
  сообщение о совпадении не показывается, вместо него — банкер деградации.
- [Блок без поля `page`] → Не отбрасывается (страница неизвестна): фильтр
  работает по известным номерам и пропускает такие блоки, чтобы не потерять
  содержимое.

## Migration Plan

Развёртывание обычное: изменение аддитивно, миграции данных и обратной
совместимости не требует. Откат — возврат предыдущей версии приложения; поле
`identical` при этом просто игнорируется клиентом, а маркеры диапазонов
возвращаются в прежний вид вместе с дублем страницы.
