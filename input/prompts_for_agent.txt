1. Первый промпт в opencode
================================================================

Инициализируй проект веб-приложения для сравнения двух версий документов
(пока только docx с заделом на xlsx и pdf). На этом шаге нужен только минимальный рабочий каркас для файлов docx.

## ЗАДАЧА

1. Создай корень проекта `file_compare/` с базовой структурой Flask-приложения
   (фабрика create_app, минимальный роутинг: GET / и GET /health).
2. Инициализируй виртуальное окружение `python -m venv .venv`, используй python3.11 и установи
   зависимости: flask, python-dotenv, langchain-openai, pytest.
3. Настрой проект как docker-friendly: конфигурация через переменные окружения,
   пути относительные, без жёстко заданных абсолютных путей.
4. Создай `.env.example` с переменными:
   - FLASK_APP, FLASK_DEBUG, SECRET_KEY
   - LLM_BASE_URL=http://172.16.48.122:8002/v1, LLM_API_KEY, LLM_MODEL
   - UPLOAD_DIR, MAX_CONTENT_LENGTH, ALLOWED_EXTENSIONS=.docx
5. Создай `.gitignore` (исключить .venv, .env, __pycache__, uploads/, .pytest_cache).
6. Создай `requirements.txt` с зависимостями: flask, python-dotenv, langchain-openai.
   Создай `README.md` с инструкцией по запуску.
7. Инициализируй git-репозиторий и сделай первый коммит.
8. Инициализируй OpenSpec (`openspec init`) и заполни `openspec/project.md`
   базовыми конвенциями проекта.

## КРИТЕРИИ ПРИЁМКИ

- `flask run` запускает приложение, GET / отдаёт страницу (200),
  GET /health возвращает {"status": "ok"}.
- `pytest` проходит (хотя бы один базовый тест на создание приложения).
- `.env.example` содержит все нужные переменные без реальных секретов.
- Git-репозиторий создан, первый коммит сделан.
- Структура проекта логична и готова к наращиванию функциональности
  в следующих change-предложениях.

## ЧЕГО НЕ ДЕЛАТЬ

Не реализовывать парсинг файлов, LLM-вызовы, drag-and-drop, визуализацию diff.
Не писать Dockerfile (это добавится позже отдельным change'ом).

## ДОПОЛНИТЕЛЬНО
Перед началом обязательно спроси меня, что тебе не понятно.



=========================================================
2. Первый промпт в openspec
=========================================================

/opsx:propose 

Я создаю веб-приложение (отдельная веб-страница) для ИИ-агента, который сравнивает две версии документов. Все требования и сценарии на русском языке в стилистике BDD (Gherkin: Feature, Scenario, Given, When, Then).

### КОНТЕКСТ И ЦЕЛЬ
Пользователь загружает два файла (исходный и измененный). Приложение конвертирует их в Markdown, выполняет алгоритмический поиск различий, а затем использует LLM для семантической классификации каждого изменения (изменено / удалено / добавлено). Результат отображается в виде side-by-side diff с цветовой подсветкой.

### ТЕХНИЧЕСКИЙ СТЕК
- Backend: Python 3.11, Flask, LangChain, python-dotenv.
- Виртуальное окружение: использовать `python -m venv .venv`.
- Запуск: стандартный `flask run` для разработки. Архитектура должна быть готова к упаковке в Docker в будущем: конфигурация через переменные окружения, относительные пути.
- Frontend: Чистые HTML, CSS, JavaScript (vanilla).
- Парсинг:
  * `.docx` → Markdown через `python-docx`.
  * `.xlsx` → Markdown через `openpyxl`. Таблицы конвертировать в Markdown-таблицы.
- Сравнение: **гибридный подход**:
  1. Алгоритмический diff через `difflib` для поиска различающихся блоков.
  2. Каждый блок отправляется в локальную LLM для семантической классификации: "изменено", "удалено", "добавлено".
- Тестирование: TDD через pytest. Использовать mock-объекты для LLM, чтобы тесты были детерминированными.

### ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
1. **Загрузка файлов**: 
   - Две кнопки: "Открыть файл 1" и "Открыть файл 2".
   - Третья кнопка: **"Начать сравнение"** — запускает процесс сравнения после загрузки обоих файлов.
   - Drag-and-Drop: пользователь может перетащить файлы из проводника в соответствующие зоны.
   - Поддерживаемые форматы: `.docx`, `.xlsx`.
   - Валидация: если формат не поддерживается — показать ошибку.
   - Кнопка "Начать сравнение" активна только после загрузки обоих файлов.
2. **Обработка**:
   - Конвертация обоих файлов в Markdown.
   - Алгоритмический поиск различий.
   - Отправка блоков в LLM для семантической классификации.
3. **Визуализация процесса обработки**:
   - Во время обработки показывать индикатор загрузки (спиннер) и статусное сообщение.
   - Статусные сообщения по этапам:
     * "Конвертация файлов..."
     * "Поиск различий..."
     * "Анализ через LLM..."
   - Это нужно, чтобы пользователь видел, что приложение работает, а не зависло.
4. **Визуализация результата (Diff Viewer)**:
   - Отображение двух файлов рядом (side-by-side).
   - Цветовая схема: желто-зелено-серая (кнопки – зеленые, рамки – желтые, текст и фоны – оттенки серого).
   - Подсветка различий:
     * **Изменено**: зеленый фон в обоих файлах.
     * **Удалено**: красный фон в файле 1.
     * **Добавлено**: желтый фон в файле 2.
   - Синхронный скролл обеих панелей.

### ОГРАНИЧЕНИЯ И БЕЗОПАСНОСТЬ
- Конфигурация только через переменные окружения (.env).
- Адрес LLM: http://172.16.48.122:8002/v1 (внутренний корпоративный сервер, совместим с OpenAI API).

### ДИЗАЙН
Минималистичный дизайн на чистом CSS. Цветовая палитра: желто-зелено-серая. Кнопки зелёные, рамки желтые, текст и фоны различных оттенков серого.

### ЗАДАЧА ДЛЯ ИИ (ШАГИ)
1. Задай уточняющие вопросы, если что-то непонятно (особенно про обработку больших Excel-таблиц и промпт для LLM).
2. Сгенерируй BDD-сценарии (Gherkin) для основных путей.
3. Предложи архитектуру проекта и requirements.txt.
4. Напиши тесты (TDD) с моками для LLM перед реализацией.
5. Реализуй backend и frontend поэтапно.

Если что-то непонятно — спроси меня перед началом генерации кода.
